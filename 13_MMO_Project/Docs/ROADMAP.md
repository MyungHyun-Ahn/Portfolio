# 로드맵
## 서버 목표
### 서버 작업 순서

`ContentsRuntime`의 [1차 구현 계획](Plan/Server/009_ContentsRuntime_1차_계획.md#phase별-구현-및-검증-순서)은 **Phase 6의 1차 구현·검증까지 완료**했다. 선행 작업인 패킷 생성기 개편과 채팅 콘텐츠 이전도 구현·검증 및 사용자 검수를 마쳤다. 완료 게시 경로의 Handle 전환도 사용자 확인을 마쳤다.

- [x] **패킷 생성기 개편:** Chatting·World 생성물 분리, 양방향 opcode 자동 등록, DTO의 수신 View 직접 역직렬화, `<클래스명>Members.inc` 공통 규약 구현·검증 및 사용자 검수 완료. [개편 기록](Plan/Server/002_패킷_생성기_추가계획.md#후속-계획-패킷-생성기-개편)



- [ ] **자동 Delegate 운영 검증 — 게임 서버 구현 후:** 실서버에 정책을 연결하고, 같은 게임 부하에서 고정 배정과 자동 인계의 프레임 시작 지연과 목적지 부하를 비교한다. [운영 검증 범위](Plan/Server/011_자동_Delegate_정책_계획.md#운영-검증-후속)

- [x] **채팅 테스트 서버 이전:** `Tests/Chatting`의 콘텐츠를 `ContentsRuntimeLib`로 옮기고 Net/Lan 왕복 검증 및 사용자 검수를 마쳤다. 구 런타임 제거는 남은 사용처를 확인한 뒤 따로 진행한다.

후속 서버 구성과 RPC 방향은 [MMO 분산 서버 구성 계획](Plan/Server/008_MMO_분산_서버_구성_계획.md)에 정리한다.

장시간 원격 부하 시험은 이번 순서의 선행 조건이 아니다.

## 클라이언트 목표

**1차 목표 — 플레이어 간 이동 동기화.** 언리얼 클라이언트 2개와 설정으로 지정한 콘솔 더미 N개가 같은 맵에서 서로의 입장·이동·정지·퇴장을 확인한다. 이동은 서버가 확정하며, 언리얼과 더미는 `ClientNetworkLib`와 게임 패킷 처리 코드를 공유한다. [플레이어 이동 동기화 계획](Plan/Client/001_플레이어_이동_동기화_계획.md)

- [x] **Phase 0 — 게임 데이터 생성기 선행:** CSV에서 서버·클라이언트 산출물 생성, `PlayerMovement` 묶음 로드와 정적 `Find()`, 파일 잠금 시 복구와 동일 입력 재생성을 검증했다. 0.7의 운영 예외는 생성기 계획에 정리했다. 실제 서버·클라이언트 연결은 별도다. [게임 데이터 생성기 계획](Plan/Common/001_게임데이터_생성기_계획.md)
- [ ] **1.1 GameClient 기반과 네트워크 연동:** `Client.sln`에 `GameClient`를 등록하고 기존 채팅 시험 서버와의 패킷 왕복·재실행을 확인한다.
- [ ] **1.2 GameServer 기반과 고정 틱 이동:** `Server.sln`에 `GameServer`를 등록하고, 소유 워커에서 엔티티마다 한 틱에 한 번만 이동하는지 확인한다.
- [ ] **1.3 콘솔 더미 루프백:** 단일 러너가 `CLIENT_COUNT`만큼 독립 세션을 구동한다. 더미 2개 기본 회귀와 2보다 큰 설정값으로 동시 입장·이동·퇴장을 검증한다.
- [ ] **1.4 GameClient·더미 통합:** UE 2개와 더미 N개를 함께 연결해 서로의 입력으로 인한 이동을 받고, 정지 후 같은 틱의 권위 좌표가 일치하는지 확인한다.

작은 작업 단위와 각 완료 기준은 [계획 문서의 Phase 체크리스트](Plan/Client/001_플레이어_이동_동기화_계획.md#구현-순서와-완료-기준)에서 관리한다.
