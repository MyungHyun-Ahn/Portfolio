# 로드맵

서버와 클라이언트 작업을 기능 단위로 묶어 아래 순서대로 하나씩 진행한다. 단계별 목적과 완료 조건, 책임 경계는 [마일스톤](MILESTONES.md)에 둔다.

**1차 완료. 다음 작업: 2차에서 `SCharacterData`를 담은 패킷의 송수신 왕복 확인.**

## 1. 게임 서버 기반 마련

- [x] 채팅 서버 시작·종료와 콘솔 두 개의 양방향 채팅 검증. 네트워크·패킷 처리·`ContentsRuntime` 기반은 [완료 기록](#완료된-작업)에 모았다.
- [x] `GameDB/Player/Character.yaml`에서 서버 전용 `SDbCharacter.h` 생성과 C++20 컴파일을 확인했다. [DBGenerator 검증 결과](Plan/Server/015_캐릭터_저장_구조와_DBGenerator_계획.md#구현-순서와-완료-기준). **DDL 생성·적용과 DB 접속은 4차다.**

## 2. 캐릭터 맵 입장과 이동 동기화

맵 데이터 생성·적재, UE 네트워크 연결, GameServer 등록·종료와 한 틱 이동은 확인했다. 아래는 남은 작업 순서다.

1. [ ] [공개 패킷 왕복과 로그인](Plan/Server/014_월드_이동과_초기_동기화.md#로그인db-연동-구현-순서): `SCharacterData` 중첩 패킷 왕복 → 두 YAML로 공개 값 변환 함수 생성 → 시험에서 `ReqLogin → CCharacter 생성 → ResLogin` 순으로 확인한다. 실제 인증·DB는 연결하지 않는다.
2. [ ] [한 맵에서 스폰과 이동](Plan/Server/013_맵_콘텐츠와_마을_이동_계획.md): 고정 맵 하나에서 소켓 없이 데이터 기반 스폰과 20 Hz 이동을 확인한다.
3. [ ] 첫 마을 배정과 예약·인계를 확인한 뒤, 빈 마을 회수를 별도로 검증한다.
4. [ ] [콘솔 더미 루프백](Plan/Client/001_OOP_기반_플레이어_이동_동기화_계획.md#구현-순서와-완료-기준): 더미 2개와 2개보다 큰 설정으로 입장·이동·퇴장을 확인한다.
5. [ ] UE 클라이언트 2개와 설정된 더미가 같은 맵에서 서로의 이동을 보고, 정지 뒤 같은 틱의 좌표가 서버와 일치하는지 확인한다.

## 3. 전투 시스템

- [ ] 전투 필드 한 곳에서 몬스터를 배치하고, 서버 이동 충돌·적중·피해·사망 판정을 연결한다.
- [ ] 플레이어가 몬스터를 처치하고, 관찰 중인 클라이언트에서 체력과 사망 결과가 일치하는지 확인한다. 드랍과 DB 저장은 완료 조건이 아니다.

## 4. DB 연동

1. [ ] [DB 상세 계획](Plan/Server/015_캐릭터_저장_구조와_DBGenerator_계획.md): 한 MySQL 인스턴스에 `AccountDB`와 `GameDB`를 구분한다. 초기 DDL을 생성하고 검토한 뒤 테스트 DB에 별도로 적용한다.
2. [ ] 실제 계정 인증과 캐릭터 조회·저장을 연결한다. 서버 재시작 후 저장한 맵을 복원하고, 다른 계정의 캐릭터 조회는 거절되는지 확인한다.

[DDL 패치 비교](Plan/Server/015_캐릭터_저장_구조와_DBGenerator_계획.md#패치-비교-모드)는 YAML 기준 → 소스 DB 기준 순서의 별도 후속이며, 4차 완료 조건은 아니다.

## 별도 후속 작업

- 자기 캐릭터 예측·보정, 지형 확장과 광역 AOI, 드랍·획득은 기본 기능 검증과 분리한다. 언리얼 MCP와 AI 아트도 맵 입장·이동의 선행 조건이 아니다.
- [자동 Delegate 운영 검증](Plan/Server/011_자동_Delegate_정책_계획.md#운영-검증-후속)은 게임 서버 구현 후 같은 부하에서 고정 배정과 자동 인계를 비교한다. 장시간 원격 부하 시험은 마일스톤의 선행 조건이 아니다.
- 후속 서버 구성과 RPC 방향은 [MMO 분산 서버 구성 계획](Plan/Server/008_MMO_분산_서버_구성_계획.md)을 따른다.
