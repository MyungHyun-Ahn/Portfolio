# 마일스톤

단계별 목표와 완료 조건을 정한다. 세부 작업과 검증 결과는 [로드맵](ROADMAP.md)에서 관리한다. 아래는 개발 순서이며, 런타임 의존 관계를 뜻하지 않는다.

```mermaid
flowchart LR
    M1[게임 서버 기반 마련] --> M2[캐릭터 맵 입장과 이동 동기화]
    M2 --> M3[전투 시스템]
    M3 --> M4[DB 연동]
```

## 1. 게임 서버 기반 마련

- **상태: 완료.** 채팅 왕복과 서버 전용 `SDbCharacter.h` 생성·C++20 컴파일을 확인했다. [로드맵의 1차 검증 기록](ROADMAP.md#1-게임-서버-기반-마련)
- **목표:** 네트워크, 패킷 처리, 콘텐츠 실행, 캐릭터 저장 구조체 생성 기반을 마련한다.
- **완료 조건:** 채팅 서버가 정상 시작·종료하고 콘솔 두 개가 양방향으로 채팅한다. [기존 채팅 검증](ROADMAP.md#완료된-작업)에 더해, YAML에서 `SDbCharacter` 헤더를 생성하고 C++에서 컴파일한다.
- **경계:** 네트워크는 연결과 패킷 송수신을, `ContentsRuntime`은 콘텐츠 실행을 맡는다. 저장 구조체만 생성하고, DDL 생성·적용과 실제 DB 연동은 4차에 둔다.

## 2. 캐릭터 맵 입장과 이동 동기화

- **목표:** 여러 캐릭터가 같은 맵에 입장해 이동할 수 있게 한다.
- **완료 조건:** 게임 클라이언트 두 개와 설정된 더미 클라이언트가 같은 맵에 입장한다. 서로의 이동과 퇴장을 확인할 수 있고, 정지 후 같은 틱의 좌표가 서버 판정과 일치한다. 이 시험은 MySQL 없이 실행한다.
- **경계:** 허브는 입장을 승인하고 캐릭터를 넘긴다. 맵은 입장한 캐릭터를 소유하고 이동을 판정한다. 클라이언트에는 서버 객체나 DB 레코드가 아닌 공개 패킷 값만 전달한다.

## 3. 전투 시스템

- **목표:** 캐릭터가 전투 필드에서 몬스터를 사냥할 수 있게 한다.
- **완료 조건:** 캐릭터가 몬스터에게 접근해 처치할 수 있다. 장애물을 통과하지 않고 사거리 밖 공격은 피해를 주지 않는다. 몬스터의 체력과 사망 결과가 관찰 중인 클라이언트에서 일치한다. 드랍과 저장은 이 단계의 완료 조건이 아니다.
- **경계:** 맵은 위치와 충돌 판정을 관리하고, 전투 규칙은 그 결과로 적중·피해·사망을 판정한다. 전투는 DB에 의존하지 않는다.

## 4. DB 연동

- **목표:** 기존 게임 흐름에 계정 인증과 캐릭터 저장·조회를 연결한다.
- **완료 조건:** 테스트 MySQL에서 인증된 계정이 자신의 캐릭터를 불러오고 마지막 로그아웃 맵을 저장한다. 서버를 재시작한 뒤 다시 로그인해도 저장한 맵을 복원하며, 다른 계정의 캐릭터는 불러올 수 없다. [DB 상세 계획](Plan/Server/015_캐릭터_저장_구조와_DBGenerator_계획.md)
- **경계:** 하나의 MySQL 인스턴스에서 `AccountDB`와 `GameDB`를 별도 스키마로 둔다. DB 연동부가 조회 결과를 서버에서 쓸 값으로 바꾸고, 맵과 전투 코드는 MySQL을 직접 호출하지 않는다. DDL 비교 도구는 완료 조건에 넣지 않는다.

각 경계의 책임과 주고받는 값은 미리 정하되, 구현은 현재 단계에 필요한 만큼만 한다. DB 연동 전에는 시험에서만 로그인 결과와 캐릭터 값을 준비하고, 게임 서버에 인증 우회는 넣지 않는다.
