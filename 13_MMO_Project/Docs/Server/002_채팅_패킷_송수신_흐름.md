# 채팅 패킷 송수신 흐름

현재 `Tests/Chatting`의 콘솔 클라이언트와 IOCP 채팅 서버를 기준으로 한다. 기존 구조처럼 네트워크 계층이 패킷을 송수신하고, 서버 콘텐츠 계층이 로그인·섹터·채팅을 처리한다. Packet Generator는 기존 수동 패킷 작성과 분기 코드만 대체한다. 생성 방법은 [Packet Generator 사용법](../../Tools/PacketGenerator/README.md)을 참고한다.

## 접속부터 채팅 가능 상태까지

클라이언트 `Main()`은 설정을 읽고 서버에 접속을 요청한다. 앱 스레드의 `Tick()`이 Mailbox에서 `Connected`를 꺼내면 `onConnect()`가 `ReqLogin`을 보낸다. 서버 `HandleReqLogin()`이 성공 응답을 보내면 클라이언트 `HandleResLogin()`이 `ReqSectorMove`를 보낸다. 서버에 섹터 등록이 끝나고 `ResSectorMove`를 확인해야 클라이언트가 `m_isReady = true`가 되어 채팅을 보낼 수 있다. 이후 클라이언트가 보내는 `HeartbeatNoti`는 응답 없이 서버의 마지막 수신 시각을 갱신한다.

## 채팅 한 줄의 왕복

1. **클라이언트 송신.** `CConsoleChatClient::SendReqMessage()`가 `SReqMessage`에 계정 번호와 메시지를 넣는다. `MakePacketReqMessage()`는 힙 버퍼에 패킷 ID와 본문을 순서대로 쓰고 `std::shared_ptr`를 반환한다. 객체용 `<<`는 같은 `CSerializableBuffer`를 `Serialize()`에 넘긴다. 콘솔은 빌더의 반환값을 `CNetClientManager::SendPacket()`에 직접 넘긴다. 세션이 Net 헤더를 준비하고 송신 큐와 실제 I/O를 관리한다.
2. **서버 수신 → 콘텐츠.** IOCP 쪽 `CNetSession::RecvCompleted()`가 Net 헤더·길이·체크섬을 검사해 완성된 패킷을 세션의 `m_recvMsgQueue`에 넣는다. 콘텐츠 쪽 `CBaseContents`가 큐에서 꺼내 `CChatContents::OnRecv()`를 호출한다. **IOCP 수신 완료 처리에서 채팅 Handle을 바로 실행하지 않는다.**
3. **분기 → 수동 Handle.** `CChatContents::OnRecv()`가 패킷 ID를 한 번 읽고 `DispatchServerPacket()`에 넘긴다. 디스패처는 `message >> packet`으로 본문을 읽고, 잘리거나 후행 바이트가 남으면 Handle을 호출하지 않는다. 정상 본문의 로그인 상태·계정·섹터·크기 검사는 수동 `CProcessPacket::HandleReqMessage()`가 담당한다. 서버 수신이 `Failed`를 반환하면 `CBaseContents`가 연결을 끊는다.
4. **서버 응답과 주변 전파.** `HandleReqMessage()`는 `ResMessage` 버퍼를 한 번 만든 뒤 송신자에게 `SendPacket()`으로 보내고, 같은 버퍼를 `SendSector()`에도 넘긴다. `SendSector()`는 주변 범위 안에서 송신자를 제외한 세션에 전파한다. 현재 복원본의 `CNetServer::SendPacket()`은 큐 등록 뒤 `PostSend()`를 시도한다. 이미 송신 중이면 큐에 남고, 완료 경로에서 이어 보낸다.
5. **클라이언트 수신 → 콘솔.** 클라이언트 세션이 완성된 패킷을 연결별 Mailbox에 넣는다. 콘솔 스레드의 `Tick()`이 이벤트를 꺼내 `OnRecv()`를 호출한다. `DispatchClientPacket()`이 ID와 본문을 읽어 `HandleResMessage()`를 호출하면, 검사를 통과한 닉네임과 메시지가 `CLogger`로 출력된다.

## 버퍼 수명과 전송 형식

| 구간 | 누가 버퍼를 유지하고 반환하는가 |
|---|---|
| 클라이언트 송신 | `SendPacket()`에 넘긴 공유 참조는 접수 시 큐에서 진행 중 I/O로 이동한다. 완료 또는 종료 정리 후 마지막 참조가 사라지면 힙 버퍼가 해제된다. 큐 등록 전 실패에는 큐 참조가 없다. |
| 클라이언트 수신 | Mailbox 이벤트가 버퍼의 공유 참조를 보유한다. 소비하거나 폐기한 뒤 마지막 참조가 사라지면 반환된다. |
| 서버의 공유 응답 | `HandleReqMessage()`가 본인·주변 전체에 넘길 때까지 참조 하나를 유지한다. 첫 세션에 넘긴 뒤에도 다음 세션에서 같은 버퍼를 써야 하기 때문이다. |
| 서버 수신 | 수신 큐에서 꺼낸 버퍼는 `OnRecv()`에 잠시 빌려준다. Handle은 역직렬화된 구조체만 받는다. `CBaseContents`가 `OnRecv()` 반환 후 수신 버퍼 참조를 내린다. |

패킷 하나는 고정 크기 버퍼 하나에 맞춰 작성한다. 공간이 부족한 필드는 쓰거나 커서를 옮기지 않고 실패로 기록한다. `MakePacket*()`은 실패하면 `nullptr`을 돌려준다. 이때 클라이언트 버퍼는 공유 참조로 해제되고 서버 버퍼는 풀에 반환된다. 여러 송신 버퍼를 한 번에 보내는 것과 개별 버퍼의 크기 제한은 별개이며, 버퍼를 늘리거나 패킷을 분할하지 않는다.

생성된 구조체는 패킷 본문만 직렬화하고, 패킷 ID는 빌더와 디스패치 경계에서 한 번씩 처리한다. Net 헤더·체크섬·인코딩은 `NetworkLib` 몫이다. 가변 채팅 문자열은 `[uint32 UTF-16 코드 단위 수][UTF-16 데이터]` 형식이다. 이전 `uint16` 바이트 수 방식과 호환되지 않으므로 서버·클라이언트를 함께 전환해야 한다.

## 코드 확인 순서

1. [`CConsoleChatClient.cpp`](../../Tests/Chatting/Client/CConsoleChatClient.cpp)의 `SendReqMessage()` → [`ClientPacketSend.g.cpp`](../../Tests/Chatting/Client/Generated/PacketHandler/ClientPacketSend.g.cpp)의 `MakePacketReqMessage()` → [`Chatting.g.h`](../../Common/Packet/Struct/Chatting/Chatting.g.h)의 `SReqMessage::Serialize()`.
2. [`CNetServer.cpp`](../../Server/NetworkLib/CNetServer.cpp)의 `RecvCompleted()` → [`CBaseContents.cpp`](../../Server/NetworkLib/CBaseContents.cpp)의 수신 큐 루프 → [`CChatContents.cpp`](../../Tests/Chatting/Server/CChatContents.cpp)의 `OnRecv()` → [`ServerPacketDispatch.g.cpp`](../../Tests/Chatting/Server/Generated/PacketHandler/ServerPacketDispatch.g.cpp).
3. [`CProcessPacket.cpp`](../../Tests/Chatting/Server/CProcessPacket.cpp)의 `HandleReqMessage()`에서 버퍼 하나를 본인과 주변에 넘기는 부분 → 클라이언트의 `HandleResMessage()`.

연산자 동작은 [`CSerializableBuffer.h`](../../Common/NetworkCommon/CSerializableBuffer.h), 클라이언트 송신 접수는 [`CNetClientManager.cpp`](../../Client/ClientNetworkLib/CNetClientManager.cpp)의 `SendPacket()`, 큐와 완료 처리는 [`CNetSession.cpp`](../../Client/ClientNetworkLib/CNetSession.cpp)에서 확인할 수 있다.
