## PCH와 헤더 의존성
- `Server/NetworkLib/pch.h` → `NetPch.h` → `MHLib/MHLibPch.h` 순서로 안정적인 의존성을 공급한다.
- MHLib의 표준·Windows·자작 헤더 의존 순서는 `Server/MHLib/includes/MHLib/MHLibPch.h`에 모았다.
- NetworkLib의 구체 타입은 PCH에 몰아넣지 않고, 각 `.cpp`의 자기 `pch.h` 다음 include에서 순서에 맞춰 공급한다.
- 일반 헤더에는 include를 두지 않는다. 헤더를 사용하는 쪽도 완전한 타입 정의의 공급 순서를 지켜야 한다.
- 컴파일된 PCH는 대상별로 분리한다. 다른 실행 프로젝트가 NetworkLib의 PCH 바이너리를 재사용하는 구성은 아니다.

## 분리 과정에서 보충한 의존성
- 원본 NetworkLib가 참조하던 내부 모니터와 크래시덤프가 분리본에 빠져 있어, 기존 05번 구현을 기준으로 연결했다.
- NetworkLib에서 사용하는 송신·작업 분배 카운터는 기존 08번 정의도 참고했다. 새로운 모니터링 체계를 설계한 것은 아니다.
- 내부 `CMonitor`, 카운터, CPU·메모리·PDH 계측과 콘솔 출력은 유지했다. 모니터링 서버 전용 접속·전송 코드는 추가하지 않았다.
- `CLanClient`는 범용 LAN 통신 코드로 유지했다.
- logger·profiler의 inline 전역 포인터는 애플리케이션에서 초기화하는 원래 책임을 유지했다. 라이브러리 링크 성공이 미초기화 상태의 서버 기동을 보장하지는 않는다.
- CP949 소스는 엄격하게 디코딩한 뒤 복사본만 UTF-8로 저장했다. 복사본의 비정상 CRCRLF 등은 LF로 정리하고 `/utf-8`을 지정했다. 원본 바이트는 변경하지 않았다.

## 빌드 방법
1. Visual Studio 2026에서 `Portfolio.sln`을 연다.
2. 구성을 `Debug`, 플랫폼을 `x64`로 선택한다.
3. 솔루션을 빌드한다. 일반 확인에는 Build를 사용하며 매번 Clean/Rebuild하지 않는다.

VS 2026 개발자 명령 프롬프트에서도 실행할 수 있다.

```bat
MSBuild.exe Portfolio.sln /t:Build /p:Configuration=Debug /p:Platform=x64
```

- 확인한 도구: v145 / MSVC 14.52.37025 / C++20 / Debug CRT `/MDd`.
- SDK는 원래의 `10.0` 선택을 유지했으며, 실행 환경의 10.0.26100.0을 확인했다.
- Win32·Release 구성 정의는 있지만 이번 빌드·실행 검증 대상은 아니다.

## 남겨둔 문제와 미검증 범위
- 초기 이전 당시 미사용 변수·형변환 경고 5건을 남겼으나, 이후 사용자 승인으로 C4101·C4267·C4311·C4302·C4312의 원인을 수정했다. 현재 v145 / x64 Debug 빌드는 경고·오류 0건이며, 경고 억제는 추가하지 않았다.
- 원본의 미사용 템플릿 분기, 빈 `GetUseCount()`, 할당·해제 짝, 참조 관리·버퍼 경계 등의 문제는 이번 단계에서 수정하지 않았다.
- 내부 모니터의 PDH 프로세스명·NIC명은 원본 설정을 유지한다. 실제 측정값의 정확성과 다른 환경에서의 계측은 미검증이다.
- 네트워크 접속·세션 종료·동시 실행·장기 부하·채팅·운영 안정성은 이번 성공 판정에 포함하지 않는다.

## 후속 경고 정리
- `CLanClient.cpp`: 미사용 `retVal` 삭제, 대기 핸들 개수의 `DWORD` 명시 변환. 개수 제한 검사나 새로운 실패 분기는 추가하지 않았다.
- `CProfileManager.h`: `PROFILE_BEGIN`의 TLS 인덱스를 `ULONG_PTR`로 받고, TLS 입출력에 `reinterpret_cast`를 사용한다. 인덱스 할당·조회·프로파일 기록 순서는 유지한다.
- 지정 경고 5종을 오류로 취급하여 수정 전 컴파일 실패를 확인하고, 수정 후 솔루션 빌드 성공과 경고·오류 0건을 확인했다.
- 실제 `PROFILE_BEGIN`으로 첫 TLS 할당, 같은 스레드의 반복 조회, 두 스레드의 인덱스 분리와 기록 횟수를 확인했다. 현재 라이브러리 전체 링크와 테스트 실행도 성공했다. 네트워크는 시작하지 않았다.
