# 클라이언트 작업 규칙

`GameClient`, 게임 콘솔 더미, 두 앱이 공유하는 클라이언트 코드에 적용한다. [공통 코딩 규칙](001_공통_코딩컨벤션.md)과 [C++ 코딩 규칙](002_Cpp_코딩컨벤션.md)을 함께 따른다. 구현 순서와 단계별 완료 조건은 [OOP 기반 플레이어 이동 동기화 계획](../Plan/Client/001_OOP_기반_플레이어_이동_동기화_계획.md)에 둔다.

## 네트워크

- 이 프로젝트의 게임 서버는 자체 `GameServer`다. 언리얼의 Dedicated Server·Listen Server와 게임 상태 동기화용 Replication·RPC는 사용하지 않는다. `CharacterMovementComponent`의 네트워크 동기화도 자체 이동 경로와 병행하지 않는다. 로컬 입력·카메라·표시·애니메이션에는 언리얼 기능을 사용한다.
- 접속·송수신·연결 종료는 저장소의 `ClientNetworkLib` 공개 기능만 사용한다. 클라이언트 앱에 별도 소켓, 언리얼 네트워크 전송 경로 또는 라이브러리 소스 복제본을 만들지 않는다.
- `ClientNetworkLib` 또는 클라이언트가 사용하는 공용 네트워크 라이브러리 수정이 필요하면, 이유와 영향 범위, 수정 없이 가능한 대안을 먼저 설명하고 사용자 승인을 받은 뒤 수정한다.

## 공용 처리와 스레드

- `Req*()`와 `Handle*()`의 요청·응답 처리 및 공용 상태는 언리얼과 더미가 같은 구현을 사용한다. 이 코드에는 `UObject`, `AActor`, `FVector`, `UE_LOG` 같은 언리얼 의존성이나 UI·렌더링·더미 테스트 전용 처리를 넣지 않는다. 생성 패킷과 디스패처는 직접 수정하지 않는다.
- 언리얼은 게임 스레드에서, 더미는 해당 세션을 맡은 앱 워커에서 `CClient::Tick()`을 호출한다. IOCP 워커에서 게임 상태나 Actor를 직접 바꾸지 않는다. 화면 표시 실패는 앱에서 처리하며 `Handle*()`의 프로토콜 실패로 반환하지 않는다.
- 연결 종료와 PIE 종료 시에는 기존 세션의 이벤트가 다음 실행의 객체에 전달되지 않도록 정리한다. 네트워크 연결을 붙인 뒤에는 같은 에디터에서 종료·재실행·재접속까지 확인한다.

## 서버 권위와 화면 표시

- 클라이언트는 목적지·정지 같은 입력 의도를 전송한다. 명령 결과와 권위 좌표는 별개다. 공용 클라이언트의 권위 좌표는 서버 상태 패킷으로만 갱신하고, Actor 위치나 보간 결과를 권위 상태로 되쓰지 않는다.
- 클릭 좌표 변환, `NetEntityId`에 대응하는 Actor의 생성·제거, 보간·애니메이션은 언리얼 쪽에서 처리한다. 더미는 Actor 없이 같은 권위 상태를 읽어 검증할 수 있어야 한다.
- 정적 게임 데이터는 생성된 클라이언트용 바이너리에서 읽고 필수 데이터를 코드 상수로 대체하지 않는다. 클라이언트 배포에 Excel·CSV·서버용 바이너리를 넣지 않는다.

## 프로젝트 변경

- `GameClient`는 `MMO_Client.sln`에 등록하고 필터를 실제 디렉터리와 맞춘다. UE 프로젝트 파일을 재생성해도 이 구성이 유지되어야 한다. 빌드 의존성을 생성된 Visual Studio 파일에만 적지 않는다.
