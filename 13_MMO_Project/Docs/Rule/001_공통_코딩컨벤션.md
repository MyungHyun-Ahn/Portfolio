# 공통 코딩 컨벤션

프로젝트 소유 코드에 적용한다. 작업 언어에 해당하는 규칙을 추가로 읽는다: [C++](002_Cpp_코딩컨벤션.md).

## 파일·명명
- UTF-8(서명없음), 신규 파일 LF. 도구 필수 예외를 제외하고 전체 개행/포맷 변경을 기능 수정과 섞지 않는다.
- 코드 식별자/소스 파일명은 영어, 기본적으로 주석은 한국어. 기술 용어와 필요한 경우에는 영어를 섞어 사용한다. 문서 파일명은 루트 `AGENTS.md`의 규칙을 따른다. 단위는 이름에 표시한다: `timeoutMilliseconds`, `queuedBytes`.
- bool은 상태/질문형으로 명명하고 의미 없는 축약을 피한다. 함수는 한 책임에 집중하며 숨은 I/O·전역 상태를 피한다.
- 외부 라이브러리는 기존 계약/스타일을 유지한다. 생성물은 원본/생성기를 수정한다.

## 오류·데이터
- 예상 가능한 실패는 결과로 구분한다. 빈 무조건 재시도·부분 실패 은폐를 금지한다.
- 로그는 원인과 안전한 추적 ID를 담고 인증정보·민감정보를 제외한다.
- 이벤트 로그는 `필드 | 본문`으로 구분한다. 왼쪽의 `key=value` 필드는 영문 키와 고정 영문 식별값 또는 숫자를 쓰고, 오른쪽에는 사람이 읽는 한국어 설명을 쓴다. 검색·필터·알림은 본문 문구가 아니라 필드 값에 의존한다.
- `Info`: 운영 중 확인해야 할 주요 상태 전이에 사용한다. 예: 서버 준비, 워커 시작, 서버 데이터 로드 완료. 반복되는 세션·콘텐츠 이벤트나 단순 사용 안내에는 사용하지 않는다.
- `Debug`: 세션 접속, 콘텐츠·섹터 진입, 채팅 처리 등 개발과 진단에 필요한 이벤트에 사용한다. 요청 처리·송신 요청·전달 완료는 구분하고, 실제 채팅 본문은 기록하지 않는다.
- `Error`: 초기화 실패, I/O 오류, 처리 실패 등 오류에 사용한다. 가능하면 실패 지점과 오류 코드를 남기고, 정상 종료는 오류로 기록하지 않는다.
- 서버가 최종 판정한다. 경계에서 길이·범위·상태·권한을 검증한다.
- 프로토콜 단일 원본/버전 호환을 지킨다. 포인터·ABI 종속 배치를 전송하지 않는다.
- 재화/보상/저장은 원자성·중복 방지·재시도·부분 실패를 정의하고 검증한다.

## 게임 데이터
- 게임의 정적 콘텐츠 정의와 수치는 코드에 하드코딩하지 않는다. 이동 속도·충돌 반경, 맵 좌표·스폰, 전투·아이템·보상 수치, 표시용 데이터는 Excel이 편집 원본이고 런타임은 여기서 생성된 대상별 바이너리를 읽는다. 생성 C++ 코드에 값·행 배열을 심지 않는다.
- 필수 데이터가 없거나 잘못됐으면 기능을 시작하지 않고 오류를 보고한다. 코드 상수·임시 기본값으로 대체하지 않는다. 필요한 기본값도 템플릿에서 정의한다.
- 게임 중 바뀌는 상태는 런타임이 소유한다. 프로토콜·파일 형식의 식별값과 버전, 기술적 안전 한도, 단위 테스트의 입력·기대값은 콘텐츠 데이터와 구분한다. 포트·워커 수 같은 운영 설정도 게임 테이블이 아니라 별도 설정에서 관리한다.

## 주석·검토
- 주석은 이유·불변식·수명/스레드 경계를 설명한다. 임시 우회에는 제거 조건을 남긴다.
- 승인 계약과 구현이 다르면 원인을 판단한 뒤 함께 수정한다. 문서만 바꿔 불일치를 숨기지 않는다.
- 정상/실패/경계 테스트를 계획하고 실제 검증과 미검증을 구분한다.
