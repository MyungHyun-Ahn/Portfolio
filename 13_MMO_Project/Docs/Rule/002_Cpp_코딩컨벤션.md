# C++ 코딩 컨벤션

[공통 규칙](001_공통_코딩컨벤션.md)을 따른다. C++ 표준·toolset·SDK·런타임 링크 설정은 라이브러리 호환 확인 후 고정한다.

## 명명
| 대상 | 규칙 | 예시 |
|---|---|---|
| 클래스 | C + PascalCase | CPlayerSession |
| 구조체 | S + PascalCase | SServerConfig |
| 인터페이스 | I + PascalCase | IGameService |
| 열거형 | E + PascalCase | ESessionState |
| 템플릿 타입 | T + PascalCase | TObjectPool |
| 일반 함수·열거 값 | PascalCase, 멤버 함수는 접근 지정별 규칙 적용 | StartWorkers(), Connected |
| 지역 변수·매개변수 | camelCase | sessionId |
| 멤버 | m_ + camelCase | m_isRunning |
| static 멤버 | sm_ + camelCase | sm_bufferPool |
| 상수 | k + PascalCase | kMaxPacketBytes |
| 포인터 변수 | p + PascalCase | pNode |
| std::shared_ptr | sp + PascalCase | spPlayer |
| std::weak_ptr | wp + PascalCase | wpItemManager |
| public 멤버 함수 | 첫 글자가 대문자 | GetSessionCount() |
| private 멤버 함수 | 첫 글자가 소문자 | closeSession() |
| 함수 out 파라미터 | out + PascalCase | outPacketBuffer |
| namespace | 최상위는 프로젝트명, 하위는 논리적 하위 디렉터리명과 동일 | NetworkLib, MHLib::containers |

- `Server`, `Tests`, `includes` 등 배치·소스 루트용 디렉터리는 네임스페이스에 포함하지 않는다. 예: `MHLib/containers/`는 `MHLib::containers`.
- 멤버 접두사와 포인터 접두사는 함께 적용한다: `m_pSession`, `m_spPlayer`, `m_wpItemManager`, `sm_spManager`.
- 락 이름은 보호 대상 뒤에 `Lock`을 붙인다(예: `m_sessionTableLock`). 읽기와 쓰기를 구분하는 락은 `RWLock`을 붙인다(예: `m_sessionTableRWLock`).
- 락을 잡는 지역 변수에도 보호 대상을 적는다. `lock`, `tableLock` 대신 `sessionTableLock`처럼 어떤 상태를 보호하는지 드러낸다.
- 조건 변수는 기다리는 조건 뒤에 `Cv`를 붙인다(예: `m_sessionTableEmptyCv`).
- 호출자가 락을 잡은 상태에서만 호출할 수 있는 함수는 이름 끝에 `Locked`를 붙인다(예: `queueSendLocked()`). 선언부 주석에 호출자가 잡아야 할 락을 명시한다. 함수 내부에서 필요한 락을 직접 잡는 경우에는, 그 이유만으로 `Locked`를 붙이지 않는다.

- 약어는 단어처럼 쓴다: `CIocpServer`.
- 새 락프리 컨테이너의 클래스명에는 `C` 뒤에 `LF`를 붙인다: `CLFSpscQueue`. 기존 타입명은 별도 작업 없이 변경하지 않는다.
- 특정 패킷을 보내는 함수는 `Send<Req|Res|Noti><기능>`으로 명명한다: `SendReqMessage()`, `SendResMessage()`, `SendNotiHeartbeat()`. 범용 `SendPacket()`이나 패킷을 만들기만 하는 `MakePacket*()`에는 적용하지 않는다.
- 주요 타입 하나를 중심으로 동명 `.h`/`.cpp`를 구성한다.

## 포맷·헤더
- **탭 폭 4, Allman, 140열**, 생성자 초기화는 선행 쉼표를 사용한다.
```cpp
CPlayerSession::CPlayerSession(ITransport& transport, const SSessionConfig& config)
	: m_transport(transport)
	, m_config(config)
{
}
```
- 함수에 `[[nodiscard]]`를 붙일 때는 함수 선언이나 정의 바로 위에 같은 들여쓰기로 한 줄에 따로 적는다. 반환 타입이 다른 함수와 같은 열에서 시작하도록 한다.
```cpp
[[nodiscard]]
bool pushPacket(std::shared_ptr<CSerializableBuffer<FALSE>> spPacket) noexcept;
```
- `switch`에서 `case` 본문을 중괄호로 묶으면, 해당 분기를 끝내는 `break;`는 닫는 중괄호 안에 둔다. 같은 본문을 공유하는 `case` 라벨은 연달아 적는다.
- 클래스의 `private` 멤버 함수와 멤버 변수는 별도 구역으로 묶는다. 함수 구역 뒤에 변수 구역이 이어지면, 접근 수준이 같아도 변수 구역 앞에 `private:`를 다시 적는다.
- include 자동 정렬을 하지 않는다. PCH 사용 대상은 해당 프로젝트 PCH를 `.cpp` 첫 include로 둔다. 다른 프로젝트 PCH는 사용하지 않는다.
- 포인터/참조는 전방 선언을 우선한다. 값 멤버·상속·템플릿에 필요한 선언은 실제로 공급한다.
- 일반 헤더에는 `#include`를 작성하지 않는다. PCH용 include 집계 헤더는 예외로 한다. 필요한 완전한 타입 정의는 PCH 또는 사용하는 `.cpp`의 선행 include로 공급한다.
- 미리 컴파일된 헤더(pch.h)에는 변경이 잦지 않은 헤더 파일 혹은 스탠다드 라이브러리의 include만 허용한다.
- VisualStudio 솔루션의 필터와 실제 파일 구조를 맞춘다.
- main 함수는 항상 파라미터를 받지 않는 int main(void); 와 같은 선언으로 사용한다.
- main 함수에서 파라미터를 받는 대신 Config를 만들어 MHLib\utils\CFileLoader.h를 사용해 로드하여 사용한다. 
- 모든 로그는 printf나 std::cout이 아닌 Server\MHLib\includes\MHLib\utils\CLogger.h로 남긴다.

## 람다
- 람다 없이 같은 흐름을 읽기 쉽게 표현할 수 있으면 람다를 쓰지 않는다. 호출할 대상이 정해져 있으면 직접 호출하고, 이름이 필요하면 일반 함수나 멤버 함수를 우선한다.
- 테스트 편의만을 위해 운영 코드의 직접 호출을 람다나 콜백으로 바꾸지 않는다. 테스트는 운영 코드의 기존 경계에 맞춘다.

## 소유권·오류
- 단독 소유는 `unique_ptr`, 실제 공유 수명만 `shared_ptr`. 일반 raw pointer는 비소유 nullable 참조, non-null 인자는 참조를 우선한다.
- 풀/intrusive/lock-free raw 소유는 Acquire/Release·완료·재사용 수명을 명시하고 검증한다. 기존 수명 계약을 임의 치환하지 않는다.
- 서버 콘텐츠는 `MakePacket()`이 반환한 `ServerNetworkLib::SendPacketPtr`로 송신하며, 패킷 버퍼의 `IncreaseRef()`·`DecreaseRef()`·`Free()`를 직접 호출하지 않는다. 호출자 참조는 핸들이, 큐에 등록된 참조는 네트워크 계층이 관리한다.
- 자원/락은 RAII. 불필요한 복사/이동은 삭제하고 const 정확성을 지킨다. 변환 생성자 `explicit`, 중요 결과 `[[nodiscard]]`, 보장 가능한 경우 `noexcept`를 사용한다.
- 예상 실패는 bool/도메인 결과 코드로 구분한다. `outError` 등 출력 인자의 유효 조건을 명시한다.
- 예외는 명시된 경계에서 처리한다. 무시하거나 OS/worker 콜백 밖으로 무작정 전파하지 않는다.

## 동시성·네트워크
- 세션·버퍼·완료/종료·재사용은 IOCP 계약을 따른다. backend 내부 차이를 콘텐츠에 누출하지 않는다.
- 공유 상태 보호와 락 순서를 명시한다. mutex는 `lock_guard`/`unique_lock`, atomic은 기본 seq_cst를 우선한다.
- 완화된 memory order는 happens-before 근거와 검증이 필요하다.
- 락 안의 외부 콜백/전송/DB 호출과 네트워크 완료 worker의 긴 블로킹 작업을 피한다. 예외는 범위·근거·데드락 검토를 기록한다.
- borrowed view 수명, payload 길이, backpressure/slow consumer/close 원인을 검증한다.

## 클라이언트 패킷 핸들러
- 생성 디스패처는 역직렬화와 잔여 바이트를 검사한다. 수동 `Handle*()`는 현재 상태·계정·요청값과 응답이 일치하는지 검사하고, 검증을 통과한 뒤 상태를 변경한다.
- 콘솔과 DummyClient가 공유하는 `HandleRes*()` 본체와 공통 상태는 `CChatNetClient`에 둔다. 콘솔 출력과 더미 검증 상태는 각 앱에 둔다. 구체적인 적용 순서는 [공통 클라이언트 응답 핸들러 계획](../Plan/Server/004_DummyClient_검증.md#공통-클라이언트-응답-핸들러)을 따른다.
- 생성 `Send*()`는 패킷 생성·송신만 한다. 응답 추적이 필요한 클라이언트 공통 요청 함수는 `Req<기능>()`으로 명명하고 `CChatNetClient`의 `protected`에 둔다(예: `ReqLogin()`). `Req*()`는 생성 `SendReq*()`를 호출하고 접수에 성공하면 기대값을 기록하며, 공통 `Handle*()`가 응답을 검증한 뒤 상태를 확정한다. 가상 `on~()`은 공통 처리 이후 앱별 후처리에만 사용한다.
- 핸들러는 `Tick()`을 호출하는 앱 스레드에서 실행한다. 핸들러에서 대기하거나 블로킹 I/O를 하지 않는다. 콜백으로 받은 `const Packet&`는 호출 중에만 사용하고, 이후 필요한 값은 복사해 보관한다.
- 현재 수신 경로에서 `Handle*()`의 `false`는 연결 종료 요청으로 이어진다. 화면 표시 실패나 테스트 기대값 불일치에는 이 반환값을 사용하지 않는다. `SendReq*()` 성공은 송신 요청 접수이고, `Ready`는 필요한 응답 검증까지 마친 상태다.

## 네트워크 라이브러리 예외 처리
- **서버:** `try`/`catch`를 사용하지 않는다. 예상치 못한 예외가 발생하면 세션을 계속 처리하지 않고 프로세스를 종료한다. 원인은 크래시 덤프로 분석한다.
- **클라이언트:** 자원을 정리하고 상태를 안전하게 되돌린 뒤 실패를 반환할 수 있는 경계에서 `try`/`catch`를 허용한다. 예를 들어 초기화 중 워커 생성이 실패하면 이미 시작한 워커와 확보한 자원을 정리하고 실패를 반환한다. 상태가 정상인지 확인할 수 없는 세션에서 예외를 삼키고 처리를 계속하지 않는다.
- **공통:** 접속 거부, 타임아웃, 연결 종료 등 예상 가능한 실패는 예외가 아니라 반환값이나 오류 코드로 처리한다.
