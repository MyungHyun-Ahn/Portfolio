# C++ 코딩 컨벤션

[공통 규칙](001_공통_코딩컨벤션.md)을 따른다. C++ 표준·toolset·SDK·런타임 링크 설정은 라이브러리 호환 확인 후 고정한다.

## 명명
| 대상 | 규칙 | 예시 |
|---|---|---|
| 클래스 | C + PascalCase | CPlayerSession |
| 구조체 | S + PascalCase | SServerConfig |
| 인터페이스 | I + PascalCase | IGameService |
| 열거형 | E + PascalCase | ESessionState |
| 템플릿 타입 | T + PascalCase | TObjectPool |
| 일반 함수·열거 값 | PascalCase, 멤버 함수는 접근 지정별 규칙 적용 | StartWorkers(), Connected |
| 지역 변수·매개변수 | camelCase | sessionId |
| 멤버 | m_ + camelCase | m_isRunning |
| static 멤버 | sm_ + camelCase | sm_bufferPool |
| 상수 | k + PascalCase | kMaxPacketBytes |
| 포인터 변수 | p + PascalCase | pNode |
| std::shared_ptr | sp + PascalCase | spPlayer |
| std::weak_ptr | wp + PascalCase | wpItemManager |
| public 멤버 함수 | 첫 글자가 대문자 | GetSessionCount() |
| private 멤버 함수 | 첫 글자가 소문자 | closeSession() |
| 함수 out 파라미터 | out + PascalCase | outPacketBuffer |
| namespace | 최상위는 프로젝트명, 하위는 논리적 하위 디렉터리명과 동일 | NetworkLib, MHLib::containers |

- `Server`, `Tests`, `includes` 등 배치·소스 루트용 디렉터리는 네임스페이스에 포함하지 않는다. 예: `MHLib/containers/`는 `MHLib::containers`.
- 멤버 접두사와 포인터 접두사는 함께 적용한다: `m_pSession`, `m_spPlayer`, `m_wpItemManager`, `sm_spManager`.

- 약어는 단어처럼 쓴다: `CIocpServer`.
- 주요 타입 하나를 중심으로 동명 `.h`/`.cpp`를 구성한다.

## 포맷·헤더
- **탭 폭 4, Allman, 140열**, 생성자 초기화는 선행 쉼표를 사용한다.
```cpp
CPlayerSession::CPlayerSession(ITransport& transport, const SSessionConfig& config)
	: m_transport(transport)
	, m_config(config)
{
}
```
- include 자동 정렬을 하지 않는다. PCH 사용 대상은 해당 프로젝트 PCH를 `.cpp` 첫 include로 둔다. 다른 프로젝트 PCH는 사용하지 않는다.
- 포인터/참조는 전방 선언을 우선한다. 값 멤버·상속·템플릿에 필요한 선언은 실제로 공급한다.
- 일반 헤더에는 `#include`를 작성하지 않는다. PCH용 include 집계 헤더는 예외로 한다. 필요한 완전한 타입 정의는 PCH 또는 사용하는 `.cpp`의 선행 include로 공급한다.
- 미리 컴파일된 헤더(pch.h)에는 변경이 잦지 않은 헤더 파일 혹은 스탠다드 라이브러리의 include만 허용한다.
- VisualStudio 솔루션의 필터와 실제 파일 구조를 맞춘다.
- main 함수는 항상 파라미터를 받지 않는 int main(void); 와 같은 선언으로 사용한다.
- main 함수에서 파라미터를 받는 대신 Config를 만들어 MHLib\utils\CFileLoader.h를 사용해 로드하여 사용한다. 

## 소유권·오류
- 단독 소유는 `unique_ptr`, 실제 공유 수명만 `shared_ptr`. 일반 raw pointer는 비소유 nullable 참조, non-null 인자는 참조를 우선한다.
- 풀/intrusive/lock-free raw 소유는 Acquire/Release·완료·재사용 수명을 명시하고 검증한다. 기존 수명 계약을 임의 치환하지 않는다.
- 자원/락은 RAII. 불필요한 복사/이동은 삭제하고 const 정확성을 지킨다. 변환 생성자 `explicit`, 중요 결과 `[[nodiscard]]`, 보장 가능한 경우 `noexcept`를 사용한다.
- 예상 실패는 bool/도메인 결과 코드로 구분한다. `outError` 등 출력 인자의 유효 조건을 명시한다.
- 예외는 명시된 경계에서 처리한다. 무시하거나 OS/worker 콜백 밖으로 무작정 전파하지 않는다.

## 동시성·네트워크
- 세션·버퍼·완료/종료·재사용은 IOCP 계약을 따른다. backend 내부 차이를 콘텐츠에 누출하지 않는다.
- 공유 상태 보호와 락 순서를 명시한다. mutex는 `lock_guard`/`unique_lock`, atomic은 기본 seq_cst를 우선한다.
- 완화된 memory order는 happens-before 근거와 검증이 필요하다.
- 락 안의 외부 콜백/전송/DB 호출과 네트워크 완료 worker의 긴 블로킹 작업을 피한다. 예외는 범위·근거·데드락 검토를 기록한다.
- borrowed view 수명, payload 길이, backpressure/slow consumer/close 원인을 검증한다.
