# 클라이언트 네트워크 분리와 콘솔 연동

상태: [1차 복원](001_1차_채팅서버_복원계획.md)의 6단계 완료. 전송 라이브러리 분리, 공용 IOCP·매니저 소유 Mailbox, 콘솔 송수신을 구현·검증하고 클라이언트 네트워크 코드 검토를 마쳤다.

서버 로그와 DummyClient 구현은 [2차 작업](../ROADMAP.md#2차-서버-로그-개선-및-dummyclient-검증)에서 다룬다.

## 목표와 변경 범위

- 클라이언트 배포 바이너리에 서버 전용 구현을 링크하지 않는다. `ServerNetworkLib`와 `ClientNetworkLib`를 분리하고, `CRingBuffer`, `CSerializableBuffer`, Net 헤더·프레이밍처럼 양쪽에서 실제 사용하는 부분만 `NetworkCommon`으로 옮긴다. 서버의 Accept·세션·콘텐츠 처리와 기존 락 정책은 바꾸지 않는다.
- `ClientNetworkLib`는 공용 IOCP 하나에 여러 접속 세션을 붙인다. 워커 수는 시작 시 `1~N` 중 설정하고, 1과 2 이상이 같은 코드 경로를 사용한다. 실행 중 워커 수 변경은 범위 밖이다. 클라이언트 네트워크(Net·LAN)는 송수신 버퍼의 할당·반환을 포함해 TLS 풀과 락프리 컨테이너를 사용하지 않는다. 필요한 곳에는 표준 컨테이너와 `std::mutex`를 사용한다. `Init()`/`Stop()` 반복은 일반 운용 시나리오로 가정하지 않지만, 워커가 다시 생겨도 TLS 슬롯 누적에 의존하지 않는다. 서버의 풀과 락 정책은 유지한다.
- 생성 클라이언트 빌더와 수동 송신 코드는 `MakeShared()`로 힙 버퍼를 만들고 `std::shared_ptr`로 넘긴다. Net은 송신 큐·진행 중 I/O와 수신 Mailbox가 소유권을 유지한다. LAN은 송신 큐·진행 중 I/O가 송신 버퍼를, 수신 뷰가 수신 저장소를 소유한다. 완성된 LAN 프레임은 복사 없이 뷰에 연결하고 분할된 프레임은 뷰가 소유하는 저장소에 조립한다. 서버 생성 빌더는 기존 `Alloc()`을 유지한다.
- 생성된 클라이언트 빌더·디스패처는 **`ChatClient` 프로젝트 소유**다. 더미는 복사본 없이 같은 생성 C++ 소스를 사용한다. 수동 핸들러 공유는 [후속 계획](004_DummyClient_검증과_메트릭_설계.md#공통-클라이언트-응답-핸들러)에서 다룬다. 별도 채팅 `.lib`나 이번 단계의 언리얼 연동은 만들지 않는다.
- **구현 전 기존 기능부터 확인한다.** 변경할 단위마다 `현행 재사용 / 경계만 수정 / 신규 필요`로 구분한다. 합치는 편이 수정량이 더 크면 함수 형태를 억지로 통일하지 않는다. 원본 `07_DummyClient`는 읽기 전용이며, 타이머/APC·전역 매니저·옛 로그인 코드는 통째로 이식하지 않는다.

## 분리 전 구조에서 유지하는 것과 바꾸는 것

| 구간 | 이전 구현 | 현재 구조 |
|---|---|---|
| 접속 | `CNetClient::Connect()`가 `connect()` + `select()`로 접속 결과를 기다리고, 연결마다 IOCP·워커를 생성 | 옛 `07_DummyClient`의 `PostConnectEx()`·`ConnectExCompleted()`를 참고해 **비동기 접속 + 매니저 공용 IOCP**로 변경 |
| 세션 | `CNetClient` 인스턴스가 소켓 하나와 송수신 상태 보유 | 기존 연결별 필드를 세션으로 옮기고, 매니저에 세션 테이블·조회·종료 책임 추가 |
| 송신 | `PrepareNetPacket()` → 큐/참조 획득 → `postSendLocked()` → 배치 완료 | 서버처럼 `WSABUF` 배열로 송신하되 클라이언트의 `deque`·`shared_ptr` 소유권과 세션별 직렬화는 유지 |
| 수신 | 클라 Net의 링버퍼 적용 전에는 `m_recvBytes` → `m_recvStream`에 누적한 뒤 완성 프레임을 복사 | 서버의 `CRingBuffer` 직접 수신 패턴을 재사용. 연결별 Mailbox에 완성 패킷을 넣고, 앱 스레드의 `Tick()`이 `onRecv()`를 호출 |
| 패킷·채팅 | 생성 `MakePacket*`·`DispatchClientPacket`과 수동 `HandleRes*` | 전송 바이트·생성 규칙·로그인→섹터→Ready 동작 유지. 실행 위치와 소비 타깃만 조정 |

생성 방식은 [Packet Generator 사용법](../../Tools/PacketGenerator/README.md), 앱의 실제 송수신 호출은 [채팅 패킷 송수신 흐름](../Server/002_채팅_패킷_송수신_흐름.md)을 본다. 아래는 현재 콘솔 구현 흐름이며, 더미·언리얼 사용은 후속 범위다.

분리 전 `CNetClient`는 소켓 하나를 직접 소유했다. 현재는 `CNetClientManager`가 실제 세션을 관리하고, 라이브러리의 `CNetClient`가 매니저 참조와 현재 `SessionId`를 보유하며 `Connect()`·`Disconnect()`·`Tick()`을 제공한다. 생성된 `CChatNetClient`는 `CNetClient`를 공개 상속하고 `IClientPacketHandler`를 비공개 상속해 채팅 `Send*()`와 수신 디스패치를 묶는다. 공통 응답 검증은 `CChatNetClientHandlers.cpp`에 있고, `CConsoleChatClient`는 검증 후 출력과 초기 섹터 요청을 담당한다.

## 1. Connect → 세션 생성 → 첫 수신

1. `CNetClientManager::Init()`에서 Winsock을 시작하고 임시 IPv4 TCP 소켓으로 `ConnectEx` 포인터를 한 번 조회한다. 임시 소켓은 닫고, 세션 소켓은 같은 Winsock 공급자로 생성해 캐시된 포인터를 재사용한다. 조회에 실패하면 초기화에 실패하며 접속을 받지 않는다. 공용 IOCP와 설정된 수의 워커는 세션마다 새로 만들지 않는다.
2. `Connect()`는 연결 시도마다 새 `SessionId`와 비공개 Mailbox를 만든다. 매니저는 같은 ID로 세션과 Mailbox를 서로 다른 `unordered_map`에 등록한다. 세션은 소켓·접속/송신/수신 `OVERLAPPED`·수신 저장소·송신 큐와 Mailbox의 쓰기용 공유 참조를 보유한다. 즉시 등록 또는 제출에 실패하면 두 항목을 남기지 않고 `0`을 반환한다. 앱에는 세션이나 Mailbox 포인터를 주지 않는다. 재접속과 매니저 `Stop()`/`Init()` 이후에도 기존 ID를 재사용하지 않는다.
3. overlapped 소켓을 로컬 주소에 `bind()`하고 공용 IOCP에 붙인 뒤 `ConnectEx()`를 건다. 성공적으로 등록된 요청은 즉시 성공 반환과 pending 모두 같은 완료 경로에서 처리한다(완료 통지를 생략하는 옵션은 사용하지 않음). 즉시 실패는 완료를 기다리지 않고 등록·자원을 되돌린다. 접속 요청 접수와 TCP 연결 성공을 별도로 알린다. 로그인 데이터는 접속 완료 후 따로 보내므로, 첫 데이터를 함께 보내지 않는 `ConnectEx`의 0바이트 성공 완료를 Recv의 0바이트 종료와 혼동하지 않는다.
4. 워커가 접속 완료를 받으면 성공 여부와 `Closing` 상태를 확인한다. `SO_UPDATE_CONNECT_CONTEXT` 적용 후 연결 상태를 설정하고 첫 수신을 건다. 같은 세션에서 `Connected`가 첫 패킷보다 먼저 앱에 전달되도록 이벤트 발행 순서를 보장한다. 첫 수신 등록의 즉시 실패나 연결 설정 실패는 성공으로 알리지 않는다. 앱은 `Connected`를 소비한 뒤 기존 로그인 흐름을 시작한다.
5. 거부·타임아웃·종료 요청은 실패 또는 취소로 구분한다. 콘솔은 `ClientConfig.conf`에서 접속 제한 시간 `CONNECT_TIMEOUT_MS`를 읽는다(생략 시 `5000`). 세션은 접속 요청마다 이 값으로 만료 시각을 계산한다. 로그인·섹터 응답 대기 시간에는 적용하지 않는다. 접속 전 실패는 `ConnectFailed`, 연결 성공을 발행한 뒤의 종료는 `Disconnected`로 구분하고 세션당 종료 결과를 한 번만 전달한다.

## 2. 세션 수명과 스레드 경계

| 소유·실행 위치 | 책임 |
|---|---|
| 매니저 | IOCP·워커·세션과 Mailbox 테이블을 소유한다. 테이블 락 안에서 이벤트를 꺼낼 수 있지만 세션 락을 기다리거나 앱 핸들러를 호출하지 않는다. |
| 네트워크 워커 `1~N` | `GetQueuedCompletionStatus()`에서 세션과 작업 종류를 식별. 서로 다른 세션은 병렬 처리하고, 같은 세션의 접속·송신·수신·종료 상태 변경은 세션 mutex로 직렬화한다. 세션에 특정 워커를 고정하지 않는다. |
| 앱 스레드 | 콘솔 루프·더미 시나리오 루프(향후 언리얼 게임 스레드)가 각 연결의 `CNetClient::Tick()`을 호출한다. 라이브러리의 `CNetClient`가 현재 ID로 `TryPopEvent()`를 호출하고, 상속한 콘텐츠 객체의 콜백을 실행한다. 하트비트와 시나리오 간격은 앱이 처리한다. |

- 상태는 `Connecting → Connected → Closing → 회수`를 기본으로 한다. 접속 실패·취소는 `Connecting → Closing`으로 간다. `Closing` 이후 새 송신/수신 등록을 막는다. 늦게 온 접속 성공도 연결을 다시 열지 않는다.
- **세션 객체 참조, 등록된 I/O 수, 패킷 버퍼 참조를 구분한다.** `m_ioCount`는 `ConnectEx`·`WSASend`·`WSARecv`를 걸기 전에 올리고, 즉시 실패 또는 성공·실패·취소 완료 소비 시 내린다. `Closing`에서 이 값이 0이 되어야 최종 정리한다. 세션 객체 자체의 수명은 `shared_ptr`로 유지하며, 완료를 소비하기 전에는 `OVERLAPPED`, 링버퍼 저장소와 진행 중인 송신 버퍼를 반환하지 않는다.
- `Disconnect()`는 해당 세션의 송신 큐가 비기를 기다리지 않고 `closesocket()`으로 소켓을 닫는다. 별도 `shutdown(SD_BOTH)`는 호출하지 않는다. 아직 전송하지 않은 패킷은 버릴 수 있지만, 등록된 I/O의 완료를 모두 소비한 뒤에 큐·진행 버퍼와 세션을 회수한다. **취소 요청 성공은 완료 소비가 아니다.** 테이블에서 뺀 뒤에도 이미 세션 참조를 얻은 호출이 끝나기 전에는 객체를 파괴하지 않는다.
- Mailbox 수명은 세션과 분리한다. 세션 회수나 `Stop()` 이후에도 기존 ID로 미처리 패킷과 종료 사유를 읽을 수 있으며, 종료 이벤트를 읽으면 매니저가 해당 항목을 제거한다. 읽지 않은 이벤트는 매니저 객체가 파괴될 때까지 남는다. `Stop()`은 I/O와 세션을 정리하지만 이벤트 소비를 기다리지 않는다.
- 매니저 Stop은 새 요청 접수 중단 → 모든 세션 종료 및 완료 소비 → 워커 종료 통지 및 join → IOCP/Winsock 정리 순서로 한다. 세션 하나가 닫힌다고 공용 워커를 종료하지 않는다. 세션 락을 잡은 채 완료나 join을 기다리지 않고, 워커 자신의 동기 Stop은 지원하지 않는다.
- 접속 타임아웃 검사와 `Stop()`은 `copySessionSnapshot()`으로 ID와 세션의 `shared_ptr`만 복사한다. 테이블 락을 풀고 각 세션을 처리하므로 세션 락과 테이블 락의 획득 순서가 뒤집히지 않는다. 스냅샷 할당 실패 시 우회 순회하거나 종료 요청을 건너뛰지 않고 프로세스를 종료한다.

## 3. SendPacket 호출 → IOCP 완료 통지

1. 앱은 `chatClient.SendReqMessage(accountNo, text)`를 호출한다. 생성 함수는 `MakePacketReqMessage()`가 만든 공유 버퍼를 `sendNetworkPacket()`으로 넘기고, `CNetClient`가 현재 ID로 매니저의 `SendPacket()`을 호출한다. 세션 ID·`Connected` 상태·큐 제한을 확인하며, 큐 진입 전 실패에는 큐 참조가 없다. 프레이밍이 버퍼를 직접 변경하므로 새 버퍼를 한 번만 제출하고 접수 후 내용이나 커서를 변경하지 않는다.
2. `PrepareNetPacket()`으로 전송 프레이밍을 적용하고, 큐 참조를 확보해 넣는다. 진행 중인 송신이 없으면 세션 락 아래 `postSendLocked()`에서 바로 송신을 건다. 별도 송신 명령 큐는 없으며, 이미 송신 중이면 완료 처리에서 다음 송신을 건다.
3. `postSendLocked()`는 큐 앞에서 최대 `kWsasendMaxBufferCount`개를 진행 중 배치로 옮겨 `WSABUF` 배열로 만든다. 첫 패킷은 기다리지 않고 송신하며, 세션당 진행 중인 `WSASend()`는 하나다. 즉시 실패 시 I/O 등록을 되돌리고 종료 경로에서 버퍼를 정리한다.
4. 성공 완료를 소비하면 배치 전체의 참조를 내리고 다음 배치를 건다. 송신 완료 바이트로 재송신하지 않는다. 실패·취소 시 등록된 완료를 모두 소비한 뒤 큐와 진행 중 배치를 정리한다. 호출 성공, 로컬 `WSASend` 완료, 상대 앱의 메시지 수신은 서로 다른 결과다.

## 4. Recv 완료 → 프레임 분리 → 클라이언트 핸들러

1. 클라이언트는 서버와 같은 공용 `CRingBuffer`를 사용한다. `ClientConfig.conf`의 `RECV_BUFFER_BYTES`(생략 시 `4096`)를 매니저 초기화에 넘기고, 이후 생성되는 세션마다 그 크기를 적용한다. 최대 Net 패킷 하나를 담지 못하거나 링버퍼 커서 범위를 넘는 값은 거부한다. 세션 링버퍼의 빈 영역을 `WSABUF`에 직접 넘기고, 끝에서 감기면 두 구간을 **한 번의 `WSARecv()`**로 건다. 세션당 진행 중인 Recv는 하나만 유지한다.
2. 완료 바이트 수만큼 `MoveRear()` 한다. Net 헤더 미완성 또는 정상 길이의 본문 미완성은 소비하지 않고 다음 수신까지 남긴다. 헤더 코드·길이 위반은 대기와 구분하여 닫는다. 완성 프레임이 여러 개면 순서대로 꺼낸다. 0바이트 TCP 수신과 실패·취소 완료도 별도로 처리한다.
3. 완성 프레임을 기존 고정 크기 `CSerializableBuffer`에 옮기고 복호화·체크섬을 확인한다. 링버퍼 내부 포인터를 앱에 넘기지 않는다. 워커는 유효한 패킷을 버퍼 참조와 함께 **세션에 이미 연결된 Mailbox에 직접 넣는다.** 연결 성공·패킷·종료 이벤트는 같은 Mailbox에서 연결별 순서를 보존한다. Mailbox 패킷 큐는 최대 512개를 받고, 큐가 가득 차거나 등록에 실패하면 세션을 종료한다. 정상 처리 후에는 링버퍼의 남은 공간에 다음 수신을 건다.
4. 앱 루프는 일반 클라의 `Tick()` 하나 또는 더미 객체들의 `Tick()`을 순회 호출한다. `CNetClient`가 자기 ID로 `TryPopEvent()`를 상한 내 호출하고, 매니저가 락을 푼 뒤 `onRecv()` 콜백을 실행한다. 생성된 `CChatNetClient`의 `onRecv()`가 `DispatchClientPacket()`으로 각 클라이언트의 `HandleRes*()`를 호출한다. **공용 수신 큐나 `sessionId → ChatClient` 수신 분배 테이블은 두지 않는다.** 처리·폐기 후 이벤트의 버퍼 참조를 반환하고, 본문 파싱이나 핸들러가 실패하면 해당 세션 ID로 종료를 요청한다. 세션 락 안에서 앱 코드를 실행하지 않는다.

## 작업 순서와 확인 기준

1단계에서 기존 `Server/NetworkLib` 경로에 `ServerNetworkLib` 프로젝트를 남기고, `CNetClient`는 `Client/ClientNetworkLib`, 공통 버퍼·프레이밍은 `Common/NetworkCommon`으로 옮겼다. `CLanClient`와 `ClientSetting`도 `ClientNetworkLib`에 둔다. 양쪽이 사용하는 수신 버퍼·뷰, `OVERLAPPED` 할당기, 네트워크 상수와 카운터만 `NetworkCommon`으로 옮겼다. `CMonitor`는 서버 쪽에 남고 공용 카운터를 읽는다. 서버와 클라이언트 라이브러리는 서로 참조하지 않는다. `MHLib`는 기존 경로의 헤더 전용 공용 유틸리티로 유지한다. `Chatting.sln` Debug/Release x64 및 `Portfolio.sln` Release x64가 빌드되었고, `ChatClient` Release 링크 명령의 프로젝트 라이브러리 입력은 `ClientNetworkLib.lib`와 `NetworkCommon.lib`로 확인했다. Release 로컬 서버에서 기존 콘솔 클라이언트 두 개의 Ready·양방향 메시지 수신·정상 종료를 확인했다.

- [x] **기존 기능 조사와 전송 라이브러리 분리.** 서버·클라이언트·공용 코드의 빌드 입력을 분리하고, 클라이언트 Release 링크 입력에서 서버 전용 구현을 제외했다.
- [x] **공용 IOCP + 비동기 접속 + 세션 수명 구현.** `ClientLifecycle` Debug/Release x64에서 워커 1개·2개, 다중 접속, 거부·타임아웃·취소, 재접속, Mailbox 순서·격리·회수 및 `Stop()`을 확인했다.
- [x] **배치 Send + 링버퍼 Recv 연결.** `ClientLifecycle`에서 송신 FIFO·배치 완료, 분할 헤더·본문, 인접 프레임, 링 끝 감기를 확인했다. 수신 버퍼 설정의 유효·생략·잘못된 값과 Release 콘솔 두 개의 Ready·양방향 채팅을 확인했다.


`shutdown(SD_BOTH)` 제거 후 `Chatting.sln` 빌드와 `ClientLifecycle` 테스트를 Debug/Release x64에서 재실행해 통과했다. Release 루프백에서 콘솔 클라이언트 두 개의 Ready, 양방향 메시지 수신 및 세 프로세스의 정상 종료를 확인했다. 스냅샷 할당 실패·덤프 수집은 강제 검증하지 않았고, 활성 다중 버퍼 송신의 취소 완료를 강제로 재현한 결과는 확인되지 않았다.

단계마다 변경 이유, 재사용한 코드, 확인 결과를 남긴 후 검토한다. 생성기 형식 변경, 서버 송수신 개편, 송신을 일부러 지연하는 배치 최적화, 전역 스케줄러 도입, 서버 세션 한도 변경은 이번 범위에서 제외한다.
