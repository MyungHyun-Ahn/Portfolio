# 클라이언트 네트워크 분리와 DummyClient 계획

상태: 전송 라이브러리 분리, 공용 IOCP·Mailbox, 클라이언트 패킷 공유 소유권 구현 및 검증. 2단계 코드 검토 대기. Net 수신 링버퍼 전환과 DummyClient는 미착수. [복원 계획의 6단계](001_1차_채팅서버_복원계획.md)를 구체화한다.

## 목표와 변경 범위

- 클라이언트 배포 바이너리에 서버 전용 구현을 링크하지 않는다. `ServerNetworkLib`와 `ClientNetworkLib`를 분리하고, `CRingBuffer`, `CSerializableBuffer`, Net 헤더·프레이밍처럼 양쪽에서 실제 사용하는 부분만 `NetworkCommon`으로 옮긴다. 서버의 Accept·세션·콘텐츠 처리와 기존 락 정책은 바꾸지 않는다.
- `ClientNetworkLib`는 공용 IOCP 하나에 여러 접속 세션을 붙인다. 워커 수는 시작 시 `1~N` 중 설정하고, 1과 2 이상이 같은 코드 경로를 사용한다. 실행 중 워커 수 변경은 범위 밖이다. 클라이언트 네트워크(Net·LAN)는 송수신 버퍼의 할당·반환을 포함해 TLS 풀과 락프리 컨테이너를 사용하지 않는다. 필요한 곳에는 표준 컨테이너와 `std::mutex`를 사용한다. `Init()`/`Stop()` 반복은 일반 운용 시나리오로 가정하지 않지만, 워커가 다시 생겨도 TLS 슬롯 누적에 의존하지 않는다. 서버의 풀과 락 정책은 유지한다.
- 생성 클라이언트 빌더와 수동 송신 코드는 `MakeShared()`로 힙 버퍼를 만들고 `std::shared_ptr`로 넘긴다. Net은 송신 큐·진행 중 I/O와 수신 Mailbox가 소유권을 유지한다. LAN은 송신 큐·진행 중 I/O가 송신 버퍼를, 수신 뷰가 수신 저장소를 소유한다. 완성된 LAN 프레임은 복사 없이 뷰에 연결하고 분할된 프레임은 뷰가 소유하는 저장소에 조립한다. 서버 생성 빌더는 기존 `Alloc()`을 유지한다.
- 생성된 클라이언트 빌더·디스패처와 수동 채팅 핸들러는 **`ChatClient` 프로젝트 소유**다. 더미는 같은 C++ 소스를 자기 타깃에 포함하고 복사본을 두지 않는다. 향후 실제 클라이언트가 언리얼 프로젝트가 되면 그 프로젝트가 생성물과 핸들러를 관리한다. 공유할 코드는 콘솔·언리얼 UI에 의존하지 않게 두며, 별도 채팅 `.lib`나 이번 단계의 언리얼 연동은 만들지 않는다.
- **구현 전 기존 기능부터 확인한다.** 변경할 단위마다 `현행 재사용 / 경계만 수정 / 신규 필요`로 구분한다. 합치는 편이 수정량이 더 크면 함수 형태를 억지로 통일하지 않는다. 원본 `07_DummyClient`는 읽기 전용이며, 타이머/APC·전역 매니저·옛 로그인 코드는 통째로 이식하지 않는다.

## 분리 전 구조에서 유지하는 것과 바꾸는 것

| 구간 | 분리 전 구현 | 목표 구조 |
|---|---|---|
| 접속 | `CNetClient::Connect()`가 `connect()` + `select()`로 접속 결과를 기다리고, 연결마다 IOCP·워커를 생성 | 옛 `07_DummyClient`의 `PostConnectEx()`·`ConnectExCompleted()`를 참고해 **비동기 접속 + 매니저 공용 IOCP**로 변경 |
| 세션 | `CNetClient` 인스턴스가 소켓 하나와 송수신 상태 보유 | 기존 연결별 필드를 세션으로 옮기고, 매니저에 세션 테이블·조회·종료 책임 추가 |
| 송신 | `PrepareNetPacket()` → 큐/참조 획득 → `postSend()` → 부분/최종 완료 | 큐·참조·부분 완료 알고리즘 유지. 세션 ID로 대상을 찾고 같은 세션의 작업을 직렬화 |
| 수신 | `m_recvBytes` → `m_recvStream` 누적 → 프레임 복사 → 워커에서 가상 `OnRecv()` 호출 | 서버의 `CRingBuffer` 직접 수신 패턴 재사용. 연결별 Mailbox에 완성 패킷을 넣고, 앱 스레드가 기존 `OnRecv()`를 호출 |
| 패킷·채팅 | 생성 `MakePacket*`·`DispatchClientPacket`과 수동 `HandleRes*` | 전송 바이트·생성 규칙·로그인→섹터→Ready 동작 유지. 실행 위치와 소비 타깃만 조정 |

생성 방식은 [Packet Generator 사용법](../../Tools/PacketGenerator/README.md), 변경하지 않는 빌더·디스패처·직렬화 설명은 [채팅 패킷 송수신 흐름](../Server/002_채팅_패킷_송수신_흐름.md)을 본다. 위 문서는 **현행 코드** 기준이며, 아래는 구현할 **목표 흐름**이다.

분리 전 `CNetClient`는 소켓 하나를 들고 있어 사실상 연결별 세션이었다. 새 구조에서는 매니저가 실제 세션을 소유하고, 앱의 `ChatClient` 객체는 기존 `CNetClient` 상속 대신 매니저 참조와 현재 연결의 `SessionId`·Mailbox를 들고 있는다. 채팅 송신(`SendReqMessage()`)과 `OnRecv()`는 앱에 남긴다. 일반 클라는 객체 하나를, 더미는 여러 객체를 사용하며 별도 연결 래퍼를 추가하지 않는다.

## 1. Connect → 세션 생성 → 첫 수신

1. `CNetClientManager::Init()`에서 Winsock을 시작하고 임시 IPv4 TCP 소켓으로 `ConnectEx` 포인터를 한 번 조회한다. 임시 소켓은 닫고, 세션 소켓은 같은 Winsock 공급자로 생성해 캐시된 포인터를 재사용한다. 조회에 실패하면 초기화에 실패하며 접속을 받지 않는다. 공용 IOCP와 설정된 수의 워커는 세션마다 새로 만들지 않는다.
2. 앱은 **연결 시도마다 새 Mailbox**를 만들고 `Connect()`에 전달한다. 매니저는 `Connecting` 세션을 만들고 **새 `SessionId`**를 발급한다. 재접속도 새 연결이다. 같은 `ChatClient` 객체나 세션 테이블 슬롯을 재사용하더라도 이전 ID나 Mailbox는 재사용하지 않는다. 세션은 소켓·접속/송신/수신 `OVERLAPPED`·링버퍼·송신 큐를 소유하고, 전달받은 Mailbox의 수명을 보장하는 참조를 보유한다. 앱에는 세션 포인터를 주지 않는다. 슬롯 재사용 방식을 가져오면 `07_DummyClient`의 인덱스+증가 ID를 참고하되, 조회 시 전체 ID가 같은지 확인한다.
3. overlapped 소켓을 로컬 주소에 `bind()`하고 공용 IOCP에 붙인 뒤 `ConnectEx()`를 건다. 성공적으로 등록된 요청은 즉시 성공 반환과 pending 모두 같은 완료 경로에서 처리한다(완료 통지를 생략하는 옵션은 사용하지 않음). 즉시 실패는 완료를 기다리지 않고 등록·자원을 되돌린다. 접속 요청 접수와 TCP 연결 성공을 별도로 알린다. 로그인 데이터는 접속 완료 후 따로 보내므로, 첫 데이터를 함께 보내지 않는 `ConnectEx`의 0바이트 성공 완료를 Recv의 0바이트 종료와 혼동하지 않는다.
4. 워커가 접속 완료를 받으면 성공 여부와 `Closing` 상태를 확인한다. `SO_UPDATE_CONNECT_CONTEXT` 적용 후 연결 상태를 설정하고 첫 수신을 건다. 같은 세션에서 `Connected`가 첫 패킷보다 먼저 앱에 전달되도록 이벤트 발행 순서를 보장한다. 첫 수신 등록의 즉시 실패나 연결 설정 실패는 성공으로 알리지 않는다. 앱은 `Connected`를 소비한 뒤 기존 로그인 흐름을 시작한다.
5. 거부·타임아웃·종료 요청은 실패 또는 취소로 구분한다. 기존 접속 대기 상한 동작은 없애지 않고 가능한 기존 시각/폴링 경로를 재사용한다. 접속 전 실패는 `ConnectFailed`, 연결 성공을 발행한 뒤의 종료는 `Disconnected`로 구분하고 세션당 종료 결과를 한 번만 전달한다.

## 2. 세션 수명과 스레드 경계

| 소유·실행 위치 | 책임 |
|---|---|
| 매니저 | IOCP·워커·세션 테이블 소유. 테이블 mutex는 조회/등록/제거에만 사용하고, 조회한 세션은 참조를 확보한 후 테이블 락을 푼다. |
| 네트워크 워커 `1~N` | `GetQueuedCompletionStatus()`에서 세션과 작업 종류를 식별. 서로 다른 세션은 병렬 처리하고, 같은 세션의 접속·송신·수신·종료 상태 변경은 세션 mutex로 직렬화한다. 세션에 특정 워커를 고정하지 않는다. |
| 앱 스레드 | 콘솔 루프·더미 시나리오 루프(향후 언리얼 게임 스레드)가 각 `ChatClient::Tick()`을 호출한다. 객체가 현재 연결의 Mailbox를 읽고 핸들러를 실행한다. 하트비트와 시나리오 간격도 여기서 처리한다. |

- 상태는 `Connecting → Connected → Closing → 회수`를 기본으로 한다. 접속 실패·취소는 `Connecting → Closing`으로 간다. `Closing` 이후 새 송신/수신 등록을 막는다. 늦게 온 접속 성공도 연결을 다시 열지 않는다.
- **세션 객체 참조, 등록된 I/O 수, 패킷 버퍼 참조를 구분한다.** 테이블에 있는 세션을 외부 호출이 잠시 빌려 쓸 때도 수명을 확보한다. Connect/Send/Recv 각 I/O는 등록 전에 세션과 작업 컨텍스트의 수명을 확보하고, 즉시 실패면 등록 경로에서, 그 외에는 성공·실패·취소 완료를 소비하는 경로에서 한 번만 내려놓는다. 작업 사용이 끝나기 전에는 `OVERLAPPED`, 링버퍼 저장소, 진행 중인 송신 버퍼를 재사용하거나 반환하지 않는다.
- Disconnect는 해당 세션만 닫는다. 신규 작업 차단 → 필요 시 정상 종료의 제한 시간 내 송신 대기 → 남은 I/O 취소/소켓 정리 → 완료 소비 → 큐·진행 버퍼 및 세션 회수 순서를 검토한다. **취소 요청 성공은 완료 소비가 아니다.** I/O가 모두 정리된 후 테이블에서 빼도, 이미 세션 참조를 얻은 호출이 끝나기 전에는 객체를 파괴하지 않는다.
- Mailbox 수명은 세션과 분리한다. 네트워크는 `ChatClient*`가 아니라 해당 연결의 Mailbox 참조만 보유한다. 앱이 연결 종료 후에도 기존 Mailbox를 들고 있으면 마지막 이벤트를 읽을 수 있다. 재접속으로 새 Mailbox를 읽기 시작하면 옛 Mailbox의 패킷과 종료 이벤트를 새 연결에 적용하지 않는다. 세션과 앱이 모두 참조를 놓으면 읽지 않은 패킷의 버퍼 참조도 반환한다.
- 매니저 Stop은 새 요청 접수 중단 → 모든 세션 종료 및 완료 소비 → 워커 종료 통지 및 join → IOCP/Winsock 정리 순서로 한다. 세션 하나가 닫힌다고 공용 워커를 종료하지 않는다. 세션 락을 잡은 채 완료나 join을 기다리지 않고, 워커 자신의 동기 Stop은 지원하지 않는다.

## 3. SendPacket 호출 → IOCP 완료 통지

1. 앱은 `chatClient.SendReqMessage(text)`를 호출한다. 이 함수는 매니저에 `SendPacket(sessionId, MakePacketReqMessage(packet))`으로 직접 넘긴다. 매니저는 세션 ID·`Connected` 상태·큐 제한을 확인한다. 큐 진입 전 실패에는 큐 참조가 없다. 프레이밍이 버퍼를 직접 변경하므로 새 버퍼를 한 번만 제출하고 접수 후 내용이나 커서를 변경하지 않는다.
2. `PrepareNetPacket()`으로 전송 프레이밍을 적용하고, 큐 참조를 확보해 넣는다. 세션의 송신이 비어 있으면 세션 락 보호 아래 기존 `postSend()`를 사용해 바로 송신을 건다. **워커로 보내기 위한 별도 송신 명령 큐는 우선 추가하지 않는다.** 이미 송신 중이면 완료 처리에서 이어서 건다.
3. `postSend()`는 큐 앞 버퍼의 참조를 진행 중 버퍼로 넘기고, 아직 보내지 않은 바이트 구간을 `WSASend()`에 건다. 한 세션에 한 건의 Send만 진행한다. 즉시 실패 시 I/O 등록만 되돌리고 종료 경로에 맡긴다. `false`라고 호출자가 큐나 진행 버퍼 참조를 임의로 내리지 않는다.
4. 워커가 완료를 꺼내 실제 완료 바이트를 누적한다. 일부만 끝났으면 같은 버퍼의 남은 부분을 다시 건다. 전부 끝났으면 진행 중 참조를 내리고 다음 큐 항목을 건다. 실패·취소는 종료 정리에서 큐/진행 버퍼를 한 번만 반환한다. 호출 성공, 로컬 `WSASend` 완료, 상대 앱의 메시지 수신은 서로 다른 결과다. 첫 단계는 기존 반환 계약을 유지하되 큐 넣은 뒤 첫 송신에서 실패할 수 있음을 명시한다.

## 4. Recv 완료 → 프레임 분리 → 클라이언트 핸들러

1. 현재 서버의 `CNetSession::PostRecv()`를 참고해 세션 링버퍼의 빈 영역을 `WSABUF`에 직접 전달한다. 끝에서 감기면 최대 두 구간을 **한 번의 `WSARecv()`**로 건다. 세션당 진행 중인 Recv는 하나만 유지한다.
2. 완료 바이트 수만큼 `MoveRear()` 한다. Net 헤더 미완성 또는 정상 길이의 본문 미완성은 소비하지 않고 다음 수신까지 남긴다. 헤더 코드·길이 위반은 대기와 구분하여 닫는다. 완성 프레임이 여러 개면 순서대로 꺼낸다. 0바이트 TCP 수신과 실패·취소 완료도 별도로 처리한다.
3. 완성 프레임을 기존 고정 크기 `CSerializableBuffer`에 옮기고 복호화·체크섬을 확인한다. 링버퍼 내부 포인터를 앱에 넘기지 않는다. 워커는 유효한 패킷을 버퍼 참조와 함께 **세션에 이미 연결된 Mailbox에 직접 넣는다.** 연결 성공·패킷·종료 이벤트는 같은 Mailbox에서 연결별 순서를 보존한다. 링버퍼를 소비한 뒤 남은 공간에 다음 수신을 건다. 적체 시 조용히 패킷을 버리지 않도록 한도·실패 처리 기준은 구현 전에 기존 큐 정책과 대조한다.
4. 앱 루프는 일반 클라의 `Tick()` 하나 또는 더미 객체들의 `Tick()`을 순회 호출한다. 각 객체가 자기 Mailbox에서 상한 내 여러 이벤트를 꺼내고, 큐 락을 푼 뒤 `OnRecv()` → `DispatchClientPacket()` → 기존 `HandleRes*()`를 실행한다. **공용 수신 큐나 `sessionId → ChatClient` 수신 분배 테이블은 두지 않는다.** `OnRecv()`는 더 이상 전송 계층의 가상 콜백이 아니다. 처리·폐기 후 이벤트의 버퍼 참조를 반환하고, 본문 파싱이나 핸들러가 실패하면 해당 세션 ID로 종료를 요청한다. 세션 락 안에서 앱 코드를 실행하지 않는다.

## 작업 순서와 확인 기준

1단계에서 기존 `Server/NetworkLib` 경로에 `ServerNetworkLib` 프로젝트를 남기고, `CNetClient`는 `Client/ClientNetworkLib`, 공통 버퍼·프레이밍은 `Common/NetworkCommon`으로 옮겼다. `CLanClient`와 `ClientSetting`도 `ClientNetworkLib`에 둔다. 양쪽이 사용하는 수신 버퍼·뷰, `OVERLAPPED` 할당기, 네트워크 상수와 카운터만 `NetworkCommon`으로 옮겼다. `CMonitor`는 서버 쪽에 남고 공용 카운터를 읽는다. 서버와 클라이언트 라이브러리는 서로 참조하지 않는다. `MHLib`는 기존 경로의 헤더 전용 공용 유틸리티로 유지한다. `Chatting.sln` Debug/Release x64 및 `Portfolio.sln` Release x64가 빌드되었고, `ChatClient` Release 링크 명령의 프로젝트 라이브러리 입력은 `ClientNetworkLib.lib`와 `NetworkCommon.lib`로 확인했다. Release 로컬 서버에서 기존 콘솔 클라이언트 두 개의 Ready·양방향 메시지 수신·정상 종료를 확인했다.

- [ ] **기존 기능 조사와 전송 라이브러리 분리.** 분리 전 `CNetClient`, 서버의 링버퍼·프레이밍, 원본 `07_DummyClient`의 ConnectEx·세션 ID·완료 경로를 비교한다. 공통/서버/클라 빌드 입력을 분리하고, 서버 전용 `.lib`·`.obj` 없이 클라 Release가 링크되는지 확인한다. 이 단계에서는 현행 채팅 동작을 바꾸지 않는다.
- [ ] **공용 IOCP + 비동기 접속 + 세션 수명.** 워커 1개와 2개 이상에서 다중 접속, 접속 거부/타임아웃, 접속 중 취소, 한 세션 종료 후 다른 세션 유지, 재접속 시 새 ID·새 Mailbox와 옛 ID 거부, pending I/O가 있는 Stop과 워커 종료를 확인한다.
- [ ] **기존 Send 재사용 + 링버퍼 Recv 연결.** 연속 송신·부분 완료(재현이 어려우면 완료 바이트 처리 단위 검증과 실제 송수신을 구분), 즉시/완료 실패 정리, 분할 헤더·본문, 합쳐진 프레임, 링 끝 감기를 확인한다. 두 연결의 이벤트가 각 Mailbox에서 순서대로 처리되고, 옛 연결의 늦은 종료가 새 연결 상태를 바꾸지 않으며, 읽지 않은 패킷도 정리 시 반환되는지 확인한다. 현재 서버와 wire 변경 없이 왕복시킨다.
- [ ] **같은 소스를 쓰는 DummyClient 연결.** 콘솔과 더미가 동일 생성 파일과 동일 수동 핸들러를 컴파일하는지 확인한다. 루프백에서 고유 계정 두 개가 Ready까지 가고 실제 상대 메시지가 수신되는지 검증한다. 이후에만 설정으로 접속 수와 송신 간격을 조절하며 접속/Ready/수신/실패를 따로 집계한다. 로그는 기존 `CLogger`, 실행 설정은 `CFileLoader`를 우선 사용한다.

단계마다 변경 이유, 재사용한 코드, 확인 결과를 남긴 후 검토한다. 생성기 형식 변경, 서버 송수신 개편, 송신 배치 최적화, 전역 스케줄러 도입, 서버 세션 한도 변경은 이번 범위에서 제외한다.
