# 서버 개선 — 구버전 콘텐츠 런타임과 `CMonitor` 제거

상태: **Phase 0·1·2 완료. 다음 작업은 Phase 3.1 로그 스레드로 수집 전환.** Phase 번호는 이 정리 작업에만 적용한다. [ContentsRuntime 1차 구현](009_ContentsRuntime_1차_계획.md#phase별-구현-및-검증-순서)과는 별개다.

## 목표와 범위

- `ServerNetworkLib`에 남은 구 콘텐츠 실행 경로와 `CMonitor`를 제거한다. 지표를 없애는 것이 아니라 계측 책임을 나누고, 기존 로그 스레드가 수집과 게시를 실행하도록 바꾼다.
- **현행 `Server/ContentsRuntimeLib`는 제거 대상이 아니다.** `IContents`, 완료 Handle, 맵 간 `Move`, 워커 간 `Delegate`, 기존 `runWorker()`와 지역 타이머를 그대로 둔다. IOCP 수신 큐, `TryPopRecvPacket()`, `OnAccept()`·`OnClientLeave()`, `/exit`와 `CServer::Stop()`, 프로파일러 자체도 유지한다.
- 접두사 정리 이후의 지표 이름·라벨·단위·증가 지점을 유지한다. 이후 제거할 지표는 구 워커 전용 분배·스틸뿐이다. 새 계측 항목·라이브러리 프로젝트·전용 샘플링 스레드, IOCP 결함 수정, Jenkins/원격 배포·부하 검증은 범위 밖이다.

## 현재 연결과 목표 책임

현재 `ChatServer`와 `FixedMaps`의 콘텐츠는 이미 `ContentsRuntimeLib`에서 실행된다. 하지만 `CServer::Start()`는 구 `CContentsThread`도 시작한다. `SMonitorTimerEvent`가 약 1초마다 `g_monitor.Update()`를 호출하고, 채팅 서버의 로그 스레드 콜백은 그 스냅샷을 읽어서 게시만 한다. `RegisterContentTimerEvent()`는 두 서버에서 실질적으로 준비 완료 로그를 남기는 훅이다.

| 위치 | 이관 후 책임 |
|---|---|
| `MetricsLib` | Windows 호스트·프로세스의 CPU, 메모리, 페이지 폴트, 프로세스 이름, 호스트 전체의 NIC 트래픽·TCP 재전송을 수집한다. 기존 Prometheus 변환·최신 응답 게시·`/metrics`도 유지한다. `ServerNetworkLib`, 채팅, `CLogger`를 참조하지 않는다. |
| `ServerNetworkLib` / `ServerMetrics` | 네트워크 계층은 기존 IOCP 지점에서 원시 카운터만 갱신한다. `ServerMetrics`는 서버의 활성 세션, accept 완료/등록, 송수신 패킷, 송신 배치 한도, `WSASend` 호출·pending을 집계한다. 호스트 NIC/TCP 수치와 서버 자체 카운터는 합치지 않는다. `ServerMetrics`는 현재처럼 앱이 소스를 직접 빌드하며, 네트워크 계층은 이에 의존하지 않는다. |
| `ChatMetrics` | 채팅 테스트 앱의 콘텐츠 갱신, 로그인, 섹터 이동, 메시지 요청·송신 요청, 완료 프레임 카운터만 소유한다. 송신 요청을 전달 성공으로 해석하지 않는다. |
| 서버 앱 / `CLogger` | 앱이 수집기와 exporter를 소유하고 기존 `SetPeriodicCallback()`을 연결한다. 로그 스레드가 약 1초 간격으로 각 수집기를 순서대로 호출해 한 응답을 게시한다. 로거는 지표의 종류를 모르고, HTTP 워커는 마지막으로 게시된 완성 응답만 읽는다. |

## Phase별 구현 및 검증

### Phase 0 — 선행 작업과 단축키 제거 (완료)

- [x] **0.1 현행 경로 확보.** `ChatServer`·`FixedMaps`의 콘텐츠를 현행 런타임에 연결했다. [런타임 연결 및 회귀](009_ContentsRuntime_1차_계획.md)와 [기존 `/metrics` 연결 결과](006_프로메테우스_메트릭_설계.md#구현-순서와-확인-기준)를 기준선으로 쓴다.
- [x] **0.2 F1 서버 종료·F2 프로파일 저장 단축키 제거.** `SKeyboardTimerEvent` 선언·구현과 등록을 제거했다. `SMonitorTimerEvent`, `/exit`, `Stop()`, 프로파일러 자체는 남겼다. 변경 후 `Chatting.sln` x64 Release 빌드, `chat Release`, `metrics Release` 통과. F1/F2는 소스 참조가 남지 않은 것을 확인했으며 별도 키 입력 시험은 하지 않았다.
- [x] **0.3 잔존 책임 확인.** 구 워커의 모니터 타이머, 준비 로그 전용 훅, `CMonitor`의 채팅 필드, 구 워커의 분배·스틸 지표가 남아 있음을 확인했다. 전환·삭제는 아래 Phase에서 한다.

### Phase 1 — 호스트·프로세스 수집 이관

- [x] **1.1 수집 코드와 매핑을 `MetricsLib`에 분리했다.** `CSystemMetrics::Collect()`가 호스트·프로세스 지표를 호출자의 표본에 추가한다. 수집기가 PDH 쿼리와 이전 표본을 소유하고 `pdh`·`psapi` 의존성을 가진다. 구 수집기와 운영 콜백은 그대로 뒀다. x64 Release `MetricsTests`에서 프로세스 이름·메모리 지표·기존 표본 보존·첫 표본의 NIC 생략을 확인했고, 독립 소스 검수에서 차단 사항은 없었다.
- [x] **1.2 독립 확인.** 네트워크·채팅 라이브러리 의존 없이 기존 `MetricsTests`의 x64 Debug·Release `RunTests`를 통과했다. Windows API와 프로세스 메모리의 바이트 단위를 대조하고, 두 표본으로 CPU·PDH·NIC 지표와 첫 표본의 NIC 생략을 확인했다. 잘못된 프로세스 핸들로 조회하면 프로세스 지표만 생략되고 호스트 지표는 유지된다. 새 수집기는 Phase 3 전까지 운영 콜백에 붙이지 않는다.

### Phase 2 — 채팅과 서버 네트워크 카운터 분리

- [x] **2.1 채팅 카운터를 `ChatMetrics`로 옮겼다.** 기존 증가 지점과 지표명을 유지하고 공용 `CMonitor`에서 채팅 필드·열거값·매핑을 제거했다. 리셋하지 않는 64비트 누적값을 사용하며, 두 번째 표본부터 실제 경과 시간으로 초당 값을 계산한다. x64 Debug·Release `/metrics`와 Release Net/Lan 채팅 루프백을 통과했고, 독립 소스 검수에서 차단 사항은 없었다. 첫 게시의 처리율 생략과 피어 알림 쪽 카운터 증가 지점은 소스에서 확인했으며, 각각을 직접 검증하는 런타임 단언은 별도다.
- [x] **2.2 네트워크 카운터의 저장 위치와 집계 경계를 정리했다.** accept 완료·등록과 `WSASend` 호출·pending 원시 카운터를 기존 `SNetworkCounters`로 옮겼다. 기존 증가 지점과 지표명은 유지하며, Phase 3 전까지 `CMonitor`만 기존 교환·리셋 카운터를 소비한다. x64 Debug·Release `/metrics`와 Release Net/Lan 채팅 루프백을 통과했고, 독립 소스 검수에서 차단 사항은 없었다. 루프백은 pending 누계의 범위·비감소를 확인하지만 `WSA_IO_PENDING` 분기를 강제로 실행하지는 않았다.

### Phase 3 — 로그 스레드로 전환하고 `CMonitor` 제거

- [ ] **3.1 수집과 게시를 한 콜백으로 전환한다.** `ChatServer`가 사용할 서버와 수집기의 수명을 확보한 뒤 콜백을 등록한다. 한 번의 호출이 호스트·프로세스, 서버 네트워크, 채팅 값을 모아 기존 exporter에 넘긴다. 구 `SMonitorTimerEvent` 등록은 같은 변경에서 끈다. 일부 구간 카운터는 읽으면서 0으로 초기화하므로 구·신 수집기를 동시에 실행하지 않는다. 초당 계산은 목표 주기가 아니라 실제 표본 간 경과 시간을 쓰고 첫 표본의 초당 값은 생략한다.
  - `CMonitor::updateServer()`가 `SNetworkCounters`의 `m_acceptTotal`, `m_sendCallCount`, `m_sendPendingCount`를 리셋 없이 읽는 코드를 `ServerMetrics`로 옮긴다. `CServer`의 카운터 증가 지점과 기존 `net_*` 지표명은 유지한다.
- [ ] **3.2 종료와 비활성 경로를 확인한다.** 메트릭 비활성 또는 리스너 시작 실패 때 수집 콜백을 등록하지 않는다. 종료 시 콜백을 해제하고 진행 중인 호출이 끝난 뒤 exporter·수집기·참조 대상의 수명을 종료한다. 첫 게시 전 503, 수집 묶음이나 포맷 실패 시 마지막 정상 응답 유지, 일부 OS 표본만 유효하지 않으면 해당 지표만 생략하는 계약을 유지한다.
- [ ] **3.3 구 모니터와 그 의존성을 제거한다.** `/metrics` 전환 확인 후 `CMonitor.{h,cpp}`, `g_monitor`, `SMonitorSnapshot`, 모니터 전용 타이머 및 PCH·프로젝트·필터 참조를 제거한다. 구 워커의 `m_delWork`·`m_stealWork` 증가 지점, 이 두 지표의 exporter 매핑·테스트 기대값·Grafana 패널도 함께 제거한다. 현행 `Delegate` 계측으로 바꿔 끼우지 않는다.
- **완료 기준:** x64 Debug·Release `metrics` 회귀에서 호스트·프로세스와 서버 지표, 채팅 트래픽, 샘플 갱신, 비활성·포트 충돌·종료 후 포트 반환을 확인한다. 구 분배·스틸 지표가 없고 `CMonitor` 코드·빌드 참조가 남지 않는다.

### Phase 4 — 구 콘텐츠 실행 코드와 워커 제거

- [ ] **4.1 구 세션 연결만 끊는다.** `CBaseContents`의 구 Move·Leave·수신 처리와 `m_pCurrentContent`를 제거한다. 세션 반납의 `OnClientLeave()` 통지와 수신 큐 패킷 정리는 유지한다. `CServer::OnRecv()`와 두 서버의 빈 override는 프로젝트와 시험 소비자까지 호출처가 없는 것을 확인한 뒤 함께 제거한다.
- [ ] **4.2 구 워커와 이벤트 묶음을 제거한다.** `CContentsThread`, `CBaseContents`, `SContentsFrameEvent`, `SExampleTimerEvent`, 구 이벤트 타입·등록·`contentsThreadCount`와 관련 PCH·프로젝트·필터를 정리한다. 구 워커 설정과 현행 콘텐츠 워커 설정은 구분하며, IOCP 워커 기동·부분 실패 상태는 유지한다.
- [ ] **4.3 준비 신호와 시험을 정리한다.** `RegisterContentTimerEvent()` 대신 현재 의미에 맞는 훅에서 IOCP 기동 후 준비 로그를 남긴다. `event=server_ready`, `event=fixed_maps_ready`는 유지한다. 시험의 구 워커 및 함수명 기대값을 수정하되, 현행 콘텐츠의 진입·처리·퇴장이 같은 소유 워커에서 일어나는 검증은 남긴다.
- **완료 기준:** x64 Debug·Release에서 `Chatting.sln`과 `FixedMaps`를 빌드한다. `chat`, `chat-lan`, `server-options`, `metrics`, `FixedMaps` 루프백(맵 이동·완료 Handle·자동 Delegate 포함)과 수신 큐 회귀를 확인한다. 구 코드 및 시작 로그·설정·프로젝트 참조가 남지 않고 `/exit`, 맵 입장·이동·퇴장, 메트릭 게시가 유지된다.

각 Phase는 해당 코드와 최소 회귀 결과를 먼저 검토한 뒤 다음 Phase로 넘어간다. 최종 검증은 기존 [채팅 시험](../../../Tests/Chatting/test_server_event_input.py), [메트릭 시험 프로젝트](../../../Tests/Metrics/MetricsTests.vcxproj), [고정 맵 시험](../../../Tests/WorldServer/FixedMaps.vcxproj), [서버 수신 View 시험](../../../Tests/ServerRecvView/run_server_recv_view.py)을 사용한다.
