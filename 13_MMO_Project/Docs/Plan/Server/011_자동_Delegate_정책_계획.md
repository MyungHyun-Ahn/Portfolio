# Phase 6 — 교체 가능한 자동 Delegate 정책

상태: **Phase 6 1차 완료 — 정책 구현, 실제 맵 계측 루프백, 독립 검수 및 사용자 확인 완료. 실서버 연결·동일 부하 비교는 후속.** [엔트리 방문 계측](009_ContentsRuntime_1차_계획.md#엔트리-방문-시간-계측)과 [Phase 4 수동 Delegate](009_ContentsRuntime_1차_계획.md#phase-4--수동-delegate)는 유지한다.

## 책임과 정책 교체

| 구성 | 책임 |
|---|---|
| `ContentsDelegatePolicies.h` / `.cpp` | `CPersistentOverloadDelegatePolicy`를 선언·정의한다. 과부하 발견, 관찰·회복, 후보·목적지 선택, 대기·재시도·사후 평가의 규칙과 상태를 이 함수객체에 둔다. 런타임 객체나 워커에 직접 접근하지 않는다. |
| `CContentsScheduler` | 기존 주기에 엔트리 누계를 가져와 주입된 `SelectCandidate`를 호출한다. 후보가 있으면 기존 `RequestDelegate()`에 전달하고, 직전 후보의 미제출·거절·접수 결과를 다음 평가에 한 번 넘긴다. 정책 종류를 분기하거나 관찰 상태를 갖지 않는다. |
| `CContentsRuntime` | 워커 실행, 엔트리 누계 제공과 실행권 인계만 담당한다. 정책 헤더, 정책 전용 관찰 상태·API, 정책 접근용 `friend`를 추가하지 않는다. |

정책은 공통 함수객체 호출 계약을 사용한다. 정책을 바꾸려면 같은 스케줄러 생성자에 다른 함수객체를 넣는다. 실행 중 정책 핫스왑은 범위 밖이다.

```cpp
class CPersistentOverloadDelegatePolicy
{
public:
	std::optional<SDelegateCandidate> operator()(const SEntryTimings &timings,
		const std::optional<SDelegateSubmitResult> &lastSubmit);
};
```

결과는 `std::nullopt`(이동 없음) 또는 `SDelegateCandidate{instanceId, destinationWorkerIndex}` 한 건이다. `destinationWorkerIndex`는 기존 런타임의 목적지 워커 식별자다. 함수객체는 인계 요청을 직접 제출하지 않는다.

## 타이머와 정책 입력

`runWorker()`에는 엔트리 방문 블록의 지역 선언 `CScopedExecutionTimer timer(entry.timing);`만 둔다. 워커 전체 시간은 따로 재지 않는다. 스케줄러는 `TakeEntryTimings()`로 실제 워커 수와 인스턴스별 방문 누계·배정·인계 표시를 같은 스냅샷으로 넘긴다. 정책은 이 표본으로 후보 비용을 계산하므로 별도 비용 공급자가 필요 없다. 설정에는 자동 인계가 허용된 인스턴스 ID만 넘긴다. 인계 요청부터 편입 뒤 첫 수집까지 표시된 표본은 새 배정과 이전 배정의 시간이 섞일 수 있어 관찰에서 제외한다.

## 함수객체의 판단 흐름

1. **발견:** 워커별 `엔트리 방문 시간 합 / 실제 평가 간 경과 시간`을 본다. 첫 호출은 기준 시각을 잡고, 엔트리가 있으나 완료 방문이 없는 워커는 미관측으로 다룬다. 이 값은 CPU 사용률이 아니다.
2. **관찰:** 높은 부하가 반복되는 워커를 발견하면 발견 표본을 빼고 정해진 시간 동안 새 표본을 모은다. 회복하면 취소한다. 만료 시 새 표본이 충분하고 관찰 전체와 마지막 유효 구간 모두 높을 때만 후보를 검토한다. 관찰 길이와 임계값은 정책 설정이며 운영값은 부하 검증 전 확정하지 않는다.
3. **선정:** 최신 배정, 이동 가능 여부, 인스턴스 비용과 목적지 여유가 확인된 경우만 비교한다. 가장 무거운 후보를 무조건 옮기지 않고, 목적지 여유를 넘지 않으면서 두 워커의 최대 예상 부하를 가장 많이 줄이는 쌍을 고른다. 인스턴스 비용은 같은 관찰 기간의 해당 엔트리 방문 시간 합에서 계산한다. 관찰 내내 엔트리 행이 없던 워커만 빈 목적지(부하 0)로 다룬다. 인계 전환 중에는 그 순간 비어 보여도 선정하지 않는다. 근거가 부족하면 `nullopt`다.
4. **인계 이후:** 후보 반환, 요청 접수, 목적지 편입은 별개다. 후보를 반환했다고 배정이나 쿨다운을 확정하지 않는다. `RequestDelegate()`의 `true`도 접수일 뿐이다. 거절·미제출이면 새로 관찰하며 다음 후보 선정에서 거절된 쌍(미제출이면 해당 엔트리)을 제외한다. 접수되면 해당 엔트리가 목적지 실행 목록에 편입될 때까지 새 요청을 내지 않는다. 시간 초과를 취소로 보지 않는다. 편입 확인 뒤에는 전환이 섞이지 않은 새 표본으로 양쪽 부하를 보고, 양쪽 표본이 충분하고 과부하가 남으면 해당 워커를 재관찰한다. 표본이 부족하면 효과를 확정하지 않고 일반 발견 단계로 돌아간다. 직전 인스턴스의 역방향 인계는 해당 인스턴스를 검토하는 다음 후보 선정에서 제외한다.

## 구현 및 검증 범위

1. **정책 교체:** 고정 정책과 과부하 정책을 같은 스케줄러 생성자에 주입한다. 후보 반환·회복·미관측은 합성 표본으로 시험하고, 기존 인계 경로의 목적지 워커 실행을 확인한다.
2. **엔트리 계측 연결:** 실제 엔트리의 방문 시간·횟수를 수집하고, 정책은 같은 표본에서 워커별 부하와 인스턴스 비용을 계산한다. 인계 중과 편입 뒤 첫 표본으로는 판단하지 않는다.
3. **빈 워커와 재관찰:** 합성 표본으로 빈 목적지와 미관측·편입 대기를 구분하고, 제출 결과 및 편입 전후의 재관찰을 확인한다. 같은 스케줄러를 통해 처음에 엔트리가 없었던 목적지의 실제 편입과 완료 실행도 확인한다.
4. **실제 맵 계측 연결:** `FixedMaps`의 `automatic_delegate` 루프백은 테스트 맵의 실제 방문 누계를 변경 없이 정책에 넘긴다. 단발 지연에서는 미인계, 지속 지연에서는 빈 워커로 한 번 접수·편입된 뒤 기존 세션과 맵 상태로 요청이 이어지는 것을 확인했다. 기존 루프백 회귀와 신규 시나리오 모두 x64 Debug·Release에서 통과했고, 신규 시나리오는 구성별로 세 번 더 통과했다. 단발 지연의 미인계는 연결 경로에서 확인한 결과다. 이 루프백만으로는 연속 과부하 조건과 회복 조건 중 무엇이 인계를 막았는지 분리해 검증할 수 없다. 정책 분기는 실제 시각에 의존하지 않는 합성 표본 시험에서 다룬다.
5. **검수 및 완료:** 독립 검수에서 차단 사항은 없었다. 평가 경계와 실행 타이밍에 따른 표본 변동은 계측의 한계로 남는다. 현재 구현과 `FixedMaps` 연결 검증까지 사용자 확인으로 완료 처리했다.

## 운영 검증 후속

실제 게임 서버를 구현한 뒤 진행한다. 합성 정책 시험과 `FixedMaps` 루프백은 운영 부하에서의 성능 개선을 보장하지 않는다.

- [ ] 실서버에 정책을 연결하고 장시간 미편입 진단 로그를 추가한다. 현재처럼 동기 스케줄러 하나만 요청한다면 기존 요청 경로를 사용한다. 수동 또는 다른 제출자를 운영에 추가하기 전에는 낡은 출발지를 전제로 한 요청을 거절할 공통 접수 조건을 추가한다.
- [ ] 실제 게임 트래픽에서 단발 지연에 불필요한 인계가 발생하지 않는지, 지속 과부하에서 필요한 인계가 늦어지지 않는지 확인한다. 같은 부하의 고정 배정과 비교해 프레임 시작 지연이 줄고 목적지에 새로운 과부하가 생기지 않는지 확인한다.
