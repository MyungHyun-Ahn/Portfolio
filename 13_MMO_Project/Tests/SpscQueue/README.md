# SPSC 큐 캐시라인 분리 측정

## 측정 조건

- Windows x64, MSVC `/O2`, 생산자 1개와 소비자 1개를 같은 등급의 서로 다른 물리 코어에 고정했다.
- 큐 용량 1,024개, `unsigned` 50만 건 전달, 조건별 10회. 두 버전의 실행 순서를 번갈아 측정하고 매회 FIFO를 검증했다.
- 분리 전 비교군은 같은 구현에서 읽기·쓰기 인덱스의 `alignas` 두 줄만 제거했다. 측정 환경의 캐시라인 크기는 64바이트였다.
- `Sleep` 조건은 소비자가 빈 큐를 관측했을 때만 대기했다. 생산자는 큐가 차면 스핀으로 재시도했다. 로그 포맷과 출력 I/O는 포함하지 않았다.

## 초기 비교

| 소비자 대기 정책 | 타이머 설정 | 분리 전 (ms) | 분리 후 (ms) |
|---|---|---:|---:|
| 스핀 (`Sleep` 없음) | 기본 | 10.93 | 2.00 |
| `Sleep(1)` | 기본 | 2,556.59 | 87.15 |
| `Sleep(1)` | `timeBeginPeriod(1)` | 171.49 | 9.33 |
| `Sleep(2)` | `timeBeginPeriod(1)` | 257.22 | 10.27 |
| `Sleep(4)` | `timeBeginPeriod(1)` | 418.32 | 11.11 |

시간은 50만 건 전달 완료 시간의 중앙값이다. `Sleep` 없는 조건에서 처리량은 약 5.5배였다. `Sleep`이 포함된 비교는 대기 정책의 영향도 받으므로 큐 연산 자체의 배율로 보지 않는다.

## 후속 비교: 왜 `Sleep`에서 차이가 더 커졌나

`timeBeginPeriod(1)`과 `Sleep(4)`를 고정하고, 잠들기 전에 소비자가 빈 큐를 재확인하는 횟수만 바꿨다. 다음 수치는 계측을 추가한 별도 실행의 결과다.

| 잠들기 전 추가 재시도 | 완료 시간 중앙값: 분리 전 → 후 | `Sleep` 횟수 평균: 분리 전 → 후 |
|---|---:|---:|
| 없음 | 391.07 → 13.43 ms (29.1배) | 81.0 → 2.7회 |
| 최대 64회 | 54.41 → 6.55 ms (8.3배) | 10.0 → 1.1회 |
| 최대 256회 | 23.52 → 3.93 ms (6.0배) | 3.1 → 0.5회 |

재시도 없이 바로 잠드는 조건에서, 두 `Sleep` 사이에 꺼낸 건수는 평균 약 6,200건 → 18.4만 건이었다. 첫 `Sleep` 전과 마지막 `Sleep` 후 구간은 제외했다. 분리 후에는 관측 구간이 17개뿐이므로 평균은 참고용이다. `Sleep` 한 번에 걸린 시간은 평균 4.81 → 4.58 ms였다.

큰 차이는 한 번의 대기가 짧아져서가 아니라 **소비자가 다시 잠드는 횟수가 줄어서** 생겼다. 짧은 재시도를 넣자 격차가 줄었으므로, 빈 큐를 한 번 관측하자마자 밀리초 단위로 잠드는 정책이 차이를 키웠다고 볼 수 있다. 캐시 이벤트는 직접 측정하지 않았으며, 이 결과는 실제 로거의 처리량이나 적정 대기 간격을 보장하지 않는다.
