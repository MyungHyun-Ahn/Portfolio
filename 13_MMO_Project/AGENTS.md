# MMO_Project 작업 규칙
## 작업 방식
* 상위 디렉터리에 있는 프로젝트들을 포함한 기존 코드의 용어와 작업방식 등을 존중한다.
* 별도 모니터링 서버는 앞으로 사용하지 않는다. 이전·복원 시 모니터링 서버 전용 연결·전송·설정·프로토콜·프로젝트 참조는 제외하거나 새 프로젝트의 복사본에서 제거한다. 프로세스 내부의 모니터 코드와 지표 수집·출력은 유지하며, 범용 LAN 통신 코드까지 모니터링 서버 전용으로 간주하지 않는다. 보존용 원본은 수정하지 않는다.
* 변경으로 설명이 달라지는 관련 문서만 함께 갱신한다. 문서에 영향이 없는 내부 수정은 불필요한 문서를 만들지 않는다.

## 문서
### 문서 역할과 작성 위치
| 위치 | 역할과 작성할 내용 |
|---|---|
| `README.md` | 사용자를 위한 프로젝트 소개와 문서 탐색 링크를 작성한다. 세부 규칙이나 작업 계획을 중복해서 적지 않는다. |
| `AGENTS.md` | 에이전트의 작업 방식, 문서 읽기 순서와 작성 위치, Git 작업 범위를 정한다. 코딩 세부 규칙은 `Docs/Rule/`에 작성한다. |
| `Docs/ROADMAP.md` | 현재 목표, 큰 작업의 진행 순서와 상태, 완료된 작업을 요약한다. 관련 계획·기술 문서로 연결한다. |
| `Docs/Plan/` | 작업별 목적, 범위, 진행 순서, 확인 방법을 작성한다. 미확정 제안과 사용자와 합의한 내용을 구분한다. |
| `Docs/Rule/` | 공통·언어별 코딩 규칙과 프로젝트에서 지켜야 할 기준을 작성한다. |
| `Docs/Server/` | 서버 구조, 동작 흐름, 인터페이스, 소유권·수명, 스레딩 등 기술 문서를 작성한다. 설계안과 실제 구현을 구분한다. |

### 읽기와 갱신
* 작업 전 [공통 코딩 규칙](Docs/Rule/001_공통_코딩컨벤션.md)을 읽고, 작업 언어에 해당하는 규칙을 함께 읽는다.
* C++ 작업은 [C++ 코딩 규칙](Docs/Rule/002_Cpp_코딩컨벤션.md)을 함께 읽는다.
* [로드맵](Docs/ROADMAP.md)에서 현재 목표와 진행 상태를 확인하고, 현재 작업과 관련된 계획·기술 문서가 있으면 함께 읽는다. 관련 없는 문서를 매번 모두 읽을 필요는 없다.
* 로드맵은 진행 요약, 계획은 작업 방법, 서버 문서는 설계·동작 설명을 담당한다. 상세 내용은 해당 위치에 작성하고 다른 문서에서는 링크로 참조한다.
* 목표·순서·진행 상태가 바뀌면 로드맵을, 작업 범위·절차·확인 방법이 바뀌면 관련 계획을, 규칙이나 서버 설계·동작이 바뀌면 해당 규칙·기술 문서를 갱신한다.
* 필요해진 문서만 작성한다. 빈 계획·기술 문서 디렉터리를 채우기 위해 문서를 미리 만들지 않는다.
* 문서 파일명은 루트 `AGENTS.md`의 규칙을 따른다. `README.md`, `AGENTS.md`, `ROADMAP.md`는 예외다.

## Git 작업
* Git 상태·차이·이력 조회는 허용한다.
* 스테이징·커밋·푸시·브랜치 변경 등 Git 상태를 변경하는 작업은 사용자가 직접 한다.
